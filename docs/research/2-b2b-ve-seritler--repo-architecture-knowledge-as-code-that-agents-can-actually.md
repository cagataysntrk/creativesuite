## Özet

By August 2026 the "knowledge repo an agent loads before every task" has an accepted shape, and it is not a database — it is a git tree of small, schema-validated YAML/Markdown files plus a progressive-disclosure layer on top. Three standards converged: AGENTS.md (60k+ repos, now stewarded under the Linux Foundation's Agentic AI Foundation, nearest-file-wins, read by 20+ tools), Agent Skills (agentskills.io — folder + SKILL.md, three-stage discovery/activation/execution disclosure, adopted by Claude Code, Cursor, Codex, Gemini CLI, Copilot/VS Code, Goose, OpenCode and dozens more), and llms.txt v2 (revised August 2026) as the machine index. Claude Code reads CLAUDE.md, not AGENTS.md, so the canonical pattern is a one-line `@AGENTS.md` import or symlink. Concrete budgets now exist and should drive design: CLAUDE.md target <200 lines, `@` imports max 4 hops and cost full tokens at launch, `.claude/rules/*.md` with `paths:` frontmatter load only when matching files are touched, auto-memory MEMORY.md is capped at 200 lines/25KB, and invoked skills are re-attached after compaction within a 25,000-token pool (5,000 per skill). Anthropic's context-engineering guidance ("smallest set of high-signal tokens", context rot, just-in-time retrieval, sub-agents returning 1–2k-token summaries) and HumanLayer's ACE-FCA (hold 40–60% context utilization; 35k LOC feature in 7 hours) are the two most-cited measured playbooks. For validation, Zod 4 has effectively won: it is the schema layer under Astro content collections and Velite, it emits JSON Schema Draft 2020-12 via `z.toJSONSchema()`, and Standard Schema v1 makes it swappable. Contentlayer is dead (unfunded; fork = contentlayer2). For a solo operator the winning stack is: Zod → generated JSON Schema → `# yaml-language-server: $schema=` modelines for free editor autocomplete, pnpm workspaces with no build orchestrator, SOPS+age for secrets, plain-repo + Cloudflare R2 for assets, and a hand-rolled run-manifest JSON instead of MLflow/W&B.

**AGENTS.md** — 60,000+ OSS projects adopted; 20+ tools parse it (Claude Code via import, Codex, Cursor, Copilot, Jules, Aider). Stewarded by the Agentic AI Foundation under the Linux Foundation. No Turkey restriction.

**CLAUDE.md + .claude/rules/ (Claude Code memory)** — Hard numbers: target <200 lines per CLAUDE.md; imports do NOT reduce context; project-root CLAUDE.md is re-injected after /compact but nested files and path-scoped rules are not. Symlink `ln -s AGENTS.md CLAUDE.md` also works (not on Windows without dev mode). `/doctor` proposes trims. `claudeMdExcludes` lets you skip other teams' files.

**Agent Skills (agentskills.io standard)** — Implemented by Claude Code, Claude.ai, Codex/ChatGPT, Cursor, Gemini CLI, GitHub Copilot, VS Code, OpenCode, OpenHands, Goose, Letta, Roo Code, Kiro, Amp, Factory, Mistral Vibe, Laravel Boost and ~40 more. Portable across tools = no lock-in. Claude Code extends the spec with allowed-tools/disallowed-tools/subagent execution; the six spec fields work everywhere.

**Claude Code skill token budget (measured)** — This is the single most concrete token-budgeting number published for a knowledge repo in 2026. Auto-memory MEMORY.md has a parallel cap: first 200 lines or 25KB, whichever comes first.

**llms.txt (v2, Aug 2026)** — Adopted by Mintlify, GitBook, WordPress plugins; Chrome Lighthouse audits for it; OpenAI/Anthropic/Gemini publish their own. Generate yours from the validated knowledge index rather than hand-writing it. Note the `## Optional` convention maps neatly onto your free/premium context tiers.

**MCP Resources (protocol rev 2026-07-28)** — The `priority` annotation is exactly the hook you want for token budgeting (fill context by descending priority). `resources/read` may return multiple contents for a directory URI — good for 'give me the whole brand slice'. Custom URI schemes allowed, e.g. `upcy://product/<slug>`.

**Anthropic: Effective Context Engineering for AI Agents** — No quantified benchmarks published in the article itself — it is qualitative. Practical translation for you: AGENTS.md holds only pointers and invariants; the agent reads knowledge/products/<slug>/product.yaml only when the task names that product.

**HumanLayer ACE-FCA (Advanced Context Engineering / Frequent Intentional Compaction)** — Measured: 35k LOC feature (cancellation + WASM) in 7 hours; single bug fix in a 300k-LOC Rust codebase approved in 24h; a 3-person team averages ~$12k/month on Opus; an intern shipped 2 PRs day one, 10 by day eight. Key claim: reviewing research and plans beats reviewing code. Maps directly onto your creative pipelines: research(prospect) → plan(deck outline) → implement(slides).

**Zod 4** — Ecosystem gravity is decisive here: tRPC, React Hook Form resolvers, Astro, Velite. Immutable method chaining. Pair with Standard Schema so you can swap later without rewriting consumers.

**z.toJSONSchema() / z.fromJSONSchema()** — Use `io: 'input'` when generating the schema the human edits against, since your Zod schemas will have defaults/coercion. Mark `unrepresentable: 'any'` for date fields or keep dates as ISO strings in YAML (recommended).

**yaml-language-server ($schema modeline)** — Prefer the `yaml.schemas` glob map in .vscode/settings.json (committed) so new files get autocomplete without remembering the modeline. For CI use Ajv against the same generated schemas, or just run the Zod parse — don't depend on the language server for CI.

**Standard Schema v1** — The repo page did not enumerate implementers; Zod/Valibot/ArkType adoption is widely reported but treat the exact list as UNVERIFIED. StandardJSONSchemaV1 is the interesting one for your generated-schema pipeline.

**Valibot** — Published numbers from their own comparison: Valibot 1.37 kB vs Zod 17.7 kB (esbuild) / 15.18 kB (Rolldown), vs Zod Mini 6.88 kB. Runtime: ~2× faster than Zod v3, comparable to Zod v4/Zod Mini, much slower than Typia and TypeBox. Self-reported benchmarks — treat as vendor data.

**TypeBox** — Choose TypeBox only if you plan to hand-author schemas that many non-TS tools consume. Cited as much faster than Valibot/Zod at runtime in Valibot's comparison page — but validation is not your bottleneck; LLM calls are.

**Contentlayer** — Maintainers point to the community fork Contentlayer2 (github.com/timlrx/contentlayer2). Fork health for 2026 is UNVERIFIED. Do not start anything new on it.

**Velite** — Handles YAML and JSON, not just MD/MDX — important, since most of your brand/product/strategy files should be YAML, not Markdown. Built-in asset pipeline is a real bonus for a creative repo. Single-maintainer project ('© 2026 Lei') — bus-factor risk; keep your Zod schemas in your own package so Velite is replaceable.

**Astro Content Collections** — This is the reference implementation of 'human-editable files + machine-validated + editor autocomplete'. Worth reading their loader API before you write your own knowledge loader package.

**gray-matter** — MAINTENANCE FLAG: the repo README was last regenerated July 2023 and there is no confirmed 2026 release. It is feature-complete and low-risk, but treat it as frozen. SECURITY: gray-matter supports pluggable 'engines' including a JS engine — never enable non-YAML engines on files you did not write. Alternatives if you want something newer: use `yaml` (eemeli) + a hand-rolled 4-line splitter.

**MDX** — Documented downsides that matter for agents: indented code blocks do not work, autolinks unsupported, several HTML patterns incompatible, and it 'combines markdown's whitespace sensitivity with JavaScript's whitespace insensitivity'. An LLM reading raw MDX has to parse component semantics it cannot resolve. Keep knowledge/ as .md/.yaml only.

**Keystatic** — Thinkmill still labels it 'experimental'. Mitigation: your Zod schemas remain the source of truth and Keystatic is just a form renderer over the same files — if it stalls you lose a UI, not data. Config duplication between Zod and keystatic.config.ts is the real cost; consider generating the Keystatic config from Zod.

**TinaCMS** — OSS core is Apache 2.0 but the practical experience is coupled to TinaCloud. Turkey: USD billing, needs an international card.

**Decap CMS (ex-Netlify CMS)** — Rebranded from Netlify CMS in Feb 2023. 564 open issues. Still the most-starred option, which is why it keeps getting recommended — but the login/OAuth-proxy requirement disqualifies it here.

**Pages CMS** — Self-hosting requires PostgreSQL + a GitHub App, which is heavier than Keystatic local mode. Its config file convention (.pages.yml) was not confirmed on the repo page — UNVERIFIED.

**Obsidian (on the same folder)** — Best answer to 'how does the user comfortably EDIT this'. Caveat: Obsidian will not validate your YAML frontmatter against your schemas — pair it with the yaml-language-server modelines in VS Code for the structured files and use Obsidian for prose. Obsidian's own .obsidian/ folder should be gitignored or committed deliberately.

**Git LFS on GitHub** — Also: LFS cannot be used with GitHub Pages sites or template repositories. Acceptable narrow use: the ~50 MB of permanent brand assets (logos, licensed fonts, master product shots) if you want them in-repo. For thousands of generated images and demo videos, use an object store.

**DVC (Data Version Control)** — Concretely better than LFS for you because the cache is content-addressed by hash: re-generating an identical image costs zero extra storage, and you control the backend/pricing. Downside: one more CLI to learn, and dvc pull is a manual step. DVC experiments are aimed at ML runs; use your own run-manifest instead (see below).

**Cloudflare R2** — Zero egress is the decisive property for a creative repo you will repeatedly pull previews from. Turkey: fully available, USD billing, standard international card. Compare: Backblaze B2 is ~$6/TB-mo with free egress up to 3× stored (UNVERIFIED at 2026 rates).

**Run manifest JSON (hand-rolled provenance)** — Design it as a Zod schema (RunManifest) so it is validated like everything else. Record the knowledge-tree commit SHA — that is what makes a run truly replayable, since your prompts are assembled from files that change. Store cost in both USD and TRY-at-run-date if you want defensible client billing. Pointer-only for large payloads: put asset bytes in the object store and hashes in the manifest.

**Langfuse** — License is MIT for the whole repo EXCEPT the `ee/` folders. Which features live in ee/ was not confirmed — see unverified. 8,554 commits as of Aug 2026 = very active. Complements (does not replace) your run manifests: manifests are the durable git-tracked record, Langfuse is the ephemeral debugging UI.

**MLflow / Weights & Biases** — Only revisit if you start doing systematic A/B evaluation of prompt variants at volume. Even then, Langfuse datasets + your run manifests will likely be enough.

**C2PA / c2pa-rs + c2patool** — c2pa-rs is still 0.x/beta and emits C2PA v2 claims by default. No official JS/Node SDK was documented on that page (there is a separate contentauth JS project — UNVERIFIED). Practical path: shell out to c2patool from your pipeline. Note EU AI Act transparency obligations make this increasingly non-optional for ad creative.

**ExifTool + XMP sidecars** — Version 13.59, released 27 May 2026 — actively maintained. No official Node wrapper documented on the site (community wrappers exist — UNVERIFIED). RECOMMENDATION: do NOT make XMP your primary metadata store. Keep the authoritative record in your own <hash>.meta.json sidecar (rich, schema-validated, greppable) and mirror only the standard fields into the file with ExifTool.

**sqlite-vec** — Explicitly pre-v1: 'expect breaking changes'. 8k+ stars, active. Scale limits not published — irrelevant for thousands of assets. Build it as a DERIVED index in .index/ that is gitignored and rebuildable from the sidecar JSONs, so a breaking change costs you a rebuild, not data.

**LanceDB** — Heavier than sqlite-vec but genuinely multimodal, which matters when you want 'find every carousel image with a dark background and a product screenshot'. Decision rule: sqlite-vec if you only embed sidecar TEXT (prompt + caption + tags); LanceDB if you embed the IMAGES themselves.

**pnpm workspaces** — pnpm deliberately does NOT ship a task graph or build cache — that is a feature at your scale, not a gap. Adopted by Next.js, Vue, Nuxt, Vite, Prisma. Turkey: no restriction.

**Turborepo** — When you do add it, it is a ~20-line turbo.json and nothing else changes — which is precisely why deferring it is safe. Remote caching is worthless solo (you have one machine).

**Nx** — If you ever want its dependency-graph visualisation, you can run `nx graph` in a package-based repo without committing to the plugin model.

**Bun workspaces** — Bun's own benchmarks claim the Remix monorepo installs in ~500ms on Linux, 8× faster than pnpm, 28× faster than npm — vendor-published numbers. Risk: Next.js + assorted native deps still occasionally hit Bun-specific issues; pnpm is the boring correct default for a system you want to run for years.

**SOPS (getsops)** — Donated to CNCF as a Sandbox project in 2023 and now maintained by new stewards after Mozilla stepped back — governance is healthy. MPL-2.0 is file-level copyleft and irrelevant to you as a CLI consumer. Key advantage over 1Password/Doppler/Infisical for your situation: zero recurring cost, zero vendor, works offline, survives the vendor going away, and the encrypted file is backed up automatically because it is in git.

**age (+ Typage)** — v1.3.1 referenced on the repo. 'Typage' is a TypeScript implementation working in browser, Node, Deno and Bun — meaning your Next.js command center could decrypt in-process without shelling out. No cloud dependency at all, which matters for Turkey/latency/offline work.

**direnv** — The allow/deny model is the safety property that makes this acceptable: a malicious .envrc arriving via git pull cannot execute until you approve it. Add .env and any decrypted artefacts to .gitignore anyway, belt and braces.

**1Password CLI (op run / op inject)** — Linux support is implied by the bash/zsh examples but was not explicitly confirmed on the referenced page. Turkey: USD subscription, international card required. Real downside vs SOPS: your pipelines cannot run unattended without a service account, and you depend on a vendor being reachable.

**Infisical** — Self-host license split (which components are enterprise-only) was NOT stated on the pricing page — UNVERIFIED, and that ambiguity is itself a reason to defer. Doppler is the same category with the same verdict (pricing UNVERIFIED, not checked this pass).

**anthropics/skills** — 169.4k stars, 20.2k forks — by far the most-adopted example of 'knowledge packaged for agents'. Read template/ and spec/ before writing your first skill. The Creative & Design category is the closest published analogue to a brand system as code. Watch the licence line: document skills are source-available, so do not redistribute them inside a client deliverable.

**github/spec-kit** — Supports 30+ AI coding agents. The strongest available prior art for 'a repo whose primary artifact is intent, and code is downstream'. Your creative suite is the same shape with 'creative' in place of 'code'.

**Design Tokens Community Group format (DTCG)** — CRITICAL CAVEAT: the current document is a PREVIEW DRAFT (Design Tokens Format Module 2025.10, published 30 July 2026) and states outright 'Do not attempt to implement this version of the specification.' Practical move: adopt the $value/$type/alias SHAPE (which has been stable for years and is what Style Dictionary, Terrazzo and Figma consume) but validate with your OWN Zod schema, so a spec change is a schema edit, not a migration.

### Riskler

- Skill/context bloat is the failure mode that will actually bite you. Claude Code re-attaches invoked skills after compaction within a combined 25,000-token pool keeping only the first 5,000 tokens of each, filling most-recent-first — so once you have eight fat skills, the earlier ones are silently DROPPED mid-session and the agent quietly stops following instructions you believe are loaded. Mitigation: hard-cap SKILL.md size, put detail in references/, and run /context to verify what actually loaded.
- @-imports in CLAUDE.md do NOT save context — the docs state imported files load in full at launch. Splitting a 600-line CLAUDE.md into six imports feels tidy and costs exactly the same tokens. Only `.claude/rules/` with `paths:` frontmatter genuinely defers loading.
- Path-scoped rules and nested CLAUDE.md files are NOT re-injected after /compact (only the project-root CLAUDE.md is). Long agentic runs will drift back to default behaviour without any visible signal.
- The DTCG design tokens spec you would encode your brand into is a PREVIEW DRAFT that explicitly says 'Do not attempt to implement this version.' Building tooling tightly against it invites a migration. Validate with your own Zod schema over the stable $value/$type/alias shape instead.
- Contentlayer is dead and its recommended successor is a single-maintainer fork (contentlayer2). Velite is likewise essentially one maintainer. Any content-layer library you pick is a bus-factor risk — keep your Zod schemas and loader in your own package so the library is a swappable build step, not the source of truth.
- Keystatic is still labelled 'experimental' by Thinkmill after three years. Adopt it as a form renderer over files you own, never as the definition of your content model.
- gray-matter's README was last regenerated in July 2023 with no confirmed 2026 release. It is feature-complete and ubiquitous, but treat it as frozen software. Its pluggable non-YAML 'engines' can execute code — never enable them on files you did not author.
- Git LFS on GitHub is a cost trap for generated media: every push of a changed file stores a full new version forever against a 10 GiB quota (Free/Pro), billing is now metered rather than pre-paid, and with no payment method on file your pushes are simply BLOCKED at quota. LFS also cannot be used with GitHub Pages or template repos.
- sqlite-vec is explicitly pre-v1 with 'expect breaking changes'. Only safe if your index is a derived, gitignored artifact rebuildable from sidecar JSONs. Never let it become the only place a fact lives.
- c2pa-rs is 0.x/beta and has no confirmed official Node SDK — you will be shelling out to a beta CLI. Also, C2PA manifests signed with a self-signed certificate carry no external trust; publicly-trusted signing certificate costs are unverified.
- Committing an encrypted SOPS file to git means the ciphertext is permanent and public if the repo ever is. Your entire security rests on the age secret key never entering the repo and being backed up somewhere you can actually recover it. Losing that key loses all twenty API keys at once.
- LLM-generated Turkish copy will pass every schema you write and still be wrong (tone, casing of proper nouns, agglutinative suffix errors, calqued English idiom). Schema validation gives false confidence — the human approval queue is the ONLY real gate on Turkish content quality, so build it before you build automation.
- A knowledge base that only agents read will rot. If the brand handbook is not the document YOU actually open when writing, it will drift from reality within two months and silently poison every downstream generation. This is why Obsidian-over-the-same-folder matters more than any validation feature.
- Vendor pricing quoted here is USD and mostly requires an international card from Turkey; TRY FX volatility means a $199/mo tool has a very different real cost quarter to quarter. This is a strong structural argument for the free/self-hosted lane (SOPS, self-hosted Langfuse, R2 free tier) as the DEFAULT rather than the fallback.
- AGENTS.md is a convention with no required fields and no validator — nothing stops it from drifting into a 900-line dumping ground. Add a CI check that fails if AGENTS.md exceeds ~200 lines.
