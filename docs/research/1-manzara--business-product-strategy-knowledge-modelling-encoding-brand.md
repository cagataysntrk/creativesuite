## Özet

As of August 2026 there is no standard for "brand knowledge as code", but a de-facto convention has converged independently across at least four MIT-licensed OSS repos: a single foundation file — variously `.agents/brand-context.md` (arnabbagxd), `brand-context.md` (hyperfx-ai), `skills/product-marketing.md` (coreyhaines31), `data/brand.md`+`product.md`+`strategy.md` (iwe-org/marketing-workspace) — that every downstream skill reads first before writing anything. That pattern is the single most reusable finding: one canonical, short, human-editable context file, plus deeper per-topic files loaded on demand. The agent-side plumbing is now genuinely standardised: the Agent Skills spec (agentskills.io, originally Anthropic, adopted by ~40 clients) fixes SKILL.md frontmatter at `name` (≤64 chars, kebab-case, must match directory) and `description` (≤1024 chars) with `references/`, `assets/`, `scripts/` subdirs and explicit progressive-disclosure budgets (~100 tokens metadata, <5000 tokens body); AGENTS.md is stewarded by the Agentic AI Foundation under the Linux Foundation with 60k+ repos; CLAUDE.md adds path-scoped `.claude/rules/` and an auto-memory directory. On the data side, DTCG Design Tokens reached its first stable version (2025.10) so the visual half of a brand kit now has a real vendor-neutral schema; the verbal half does not, and remains prose. iwe (Apache-2.0) is the only tool found that mechanically validates markdown frontmatter against per-type schemas and exposes the graph over MCP. The marketing frameworks themselves (Dunford, StoryBrand SB7, Value Proposition Canvas, Schwartz, NN/g tone dimensions, Mark & Pearson archetypes, Kapferer prism) are stable, well-documented and directly translatable to field lists — but all are book/consultancy IP, so encode the *field structure*, not the copyrighted prose.

**Agent Skills specification (SKILL.md)** — Hard constraints: name 1-64 chars, lowercase a-z/0-9/hyphens, no leading/trailing/consecutive hyphens, MUST match parent directory name. description 1-1024 chars. Optional: license, compatibility (≤500 chars), metadata (string→string map), allowed-tools (experimental). Body budget: keep SKILL.md <500 lines / <5000 tokens; push detail into references/. Uploading to claude.ai/Skills API rejects any field outside the six spec fields with a hard error. Validator: `skills-ref validate ./my-skill`.

**CLAUDE.md + .claude/rules/ + auto memory** — Documented size target: under 200 lines per CLAUDE.md; longer files 'reduce adherence'. `@path` imports load at launch (no context saving, organisation only), max 4 hops, skipped inside backticks. Rules with `paths:` glob frontmatter load only when Claude touches matching files — the single best lever for keeping a large brand KB out of every session. Auto memory MEMORY.md loads only first 200 lines / 25KB. Claude Code does NOT read AGENTS.md — use `@AGENTS.md` import or a symlink. Managed CLAUDE.md cannot be excluded by users.

**AGENTS.md** — Now stewarded by the Agentic AI Foundation under the Linux Foundation. 60,000+ OSS projects use it. Deliberately schema-free: no required fields, just markdown headings. Common sections: project overview, build/test commands, code style, testing, security, PR guidelines. For a creative suite you would repurpose these as: what this repo is, where the brand truth lives, which pipeline to run, hard prohibitions.

**llms.txt** — Authored by Jeremy Howard, published 2024-09-03, page updated 2026-08-10, explicitly 'open for community input' — NOT backed by W3C/IETF, no enforcement, inconsistent AI-vendor compliance. Spec: only an H1 is mandatory; optional blockquote summary, free markdown, then H2-delimited sections of `- [name](url): notes` lists. Most-specific file wins when several apply (so `/brand/llms.txt` can override `/llms.txt`). The real value for you is the pattern, not the public file.

**llms-full.txt (Mintlify convention)** — Not part of the llmstxt.org spec — a downstream convention popularised by Mintlify. Mintlify also serves HTTP discovery headers. For your repo, generate it from the KB with a script rather than hand-maintaining it.

**Anthropic — Effective context engineering for AI agents** — Key operational claims: keep 'the smallest possible set of high-signal tokens'; store lightweight identifiers (paths) and load at runtime; folder hierarchies, naming conventions and timestamps are themselves signal, so name files semantically; organise prompts into distinct sections with XML tags or markdown headers; sub-agents should return 1,000-2,000 token distillations. 'Minimal doesn't mean short' — it means non-redundant.

**iwe-org/marketing-workspace** — Documented type schema (SCHEMA.md): universal optional fields description, generated{by,at}, sources[{id,resource,title,author,usage_count,last_modified}], verified{by,at}, resource, stale_after, tags, usage_window, status(draft|stable|deprecated). Per-type required fields e.g. post → stage,goal,success,platform,created (+pillar,published,engagement); experiment → stage,hypothesis,metric (+impact,confidence,ease,verdict,result); community → stage,category,resource,created; competitor → stage,resource,updated,notes. Dated filename convention for mentions/interviews (YYYY-MM-DD-*). No Turkish-language content; venues are English-language communities.

**iwe (iwe-org/iwe)** — `iwe schema` infers schemas from the store or validates on demand; validates required fields, enums, ISO dates and required sections. MCP writes are REJECTED on schema violation — this is the enforcement layer that stops agent drift. `iwe init --okf` scaffolds an Open Knowledge Format bundle. `iwe find --filter '{type: …}'` queries frontmatter. Watches files so editor edits are live.

**DTCG Design Tokens Format Module 2025.10** — Reserved $-prefixed properties: $value (required, marks a token not a group), $type (inheritable from parent group), $description, $extensions (reverse-domain vendor namespacing), $deprecated (true/false/string). Token and group names must not start with $ and must not contain { } or . — reference syntax {group.token} plus RFC 6901 JSON Pointer $ref. Groups support $root and $extends (deep-merge). Types: color, dimension {value, unit: px|rem}, fontFamily, fontWeight, duration, cubicBezier, number, and composites strokeStyle, border, transition, shadow, gradient, typography. Modern colour spaces (Display P3, Oklch, CSS Color 4) and theming for light/dark and brand variants are in scope. Split as base/semantic/component per the brand-system-skills convention.

**Zod 4** — Zod 4 is the stable line as of 2026; ~2kb gzipped core; zero dependencies; built-in JSON Schema conversion (the feature that makes the single-source-of-truth story work). **Astro Content Collections** — Supports Markdown/MDX with YAML frontmatter, plus JSON, YAML and TOML data collections and custom parsers — so a single collection concept covers both your prose files (brand/voice) and your data files (products/pricing). ### Riskler

- Framework IP: StoryBrand is a registered trademark with a paid guide-certification programme, and Dunford, Mark & Pearson, Kapferer, Aaker and Schwartz are all copyrighted books. Encoding the field structure and your own answers is fine; copying framework prose, worksheets or the official Strategyzer PDF into a repo is not, and becomes materially riskier if the repo is ever made public.
- Third-party brand corpora: design-md-hub (120 reverse-engineered design systems) and ux-skill (160 brand specs) describe other companies' trademarked identities. They are useful as format references but must never become source material for your own visual identity, and shipping them inside a public repo of yours inherits their exposure.
- Context bloat is the default failure mode: a knowledge base rich enough to be useful is too large to load every session. Without a strict index-plus-progressive-disclosure discipline (short brand-context.md, path-scoped rules, MCP resource priority annotations) the agent will either blow the context window or silently read only the first file it finds and produce confidently off-brand work.
- Single-source-of-truth drift: the moment the same fact lives in brand-context.md, positioning.yaml, a SKILL.md and a channel playbook, they will diverge, and the agent will pick one arbitrarily — Claude Code's own docs warn that contradictory instructions are resolved non-deterministically. Every fact needs exactly one owning file, with the others linking to it.
- Agent-generated content re-entering the knowledge base as fact: without generated/verified/stale_after frontmatter, a hallucinated statistic written into a draft in week one becomes a cited proof point in week six. This is the most likely concrete failure of an agentic creative suite and the reason the provenance fields are non-negotiable.
- Turkish-language quality: every OSS repo and every framework surveyed is English-language and mostly US-SaaS-shaped. Tone dimensions, hook libraries, swipe files and awareness/sophistication assessments do not transfer directly — sen/siz, loanword tolerance and register are invisible to an English tone spec, and a US-calibrated sophistication level will mis-select hooks for Turkish categories.
- Convention instability: llms.txt is explicitly not backed by any standards body and has inconsistent vendor compliance; brand.md, OKF and the .brand runtime are early with no published version numbers or adoption data. Design so that the knowledge base is plain markdown/YAML/JSON first and any convention is a thin wrapper you can drop.
- Over-schematisation: forcing brand narrative, founder voice and cultural nuance into rigid YAML strips exactly the material that makes output distinctive. Keep the raw/synthesis split used by the brand-discovery skill — verbatim quotes and stories in prose, only the derived decisions in structured fields.
- Licence heterogeneity in dependencies: anthropics/skills splits Apache-2.0 for most skills but SOURCE-AVAILABLE (not open source) for the docx/pdf/pptx/xlsx document skills you would most want for the decks pipeline; Diátaxis is CC-BY-SA 4.0 (share-alike on republication); several brand repos have unverified licences. Check before redistributing anything.
- Platform automation ToS: none of the surveyed knowledge repos address whether automated posting is permitted on the destination platforms. Instagram, LinkedIn and TikTok each have distinct rules on automated publishing and AI-disclosure, and EU AI Act Article 50 style disclosure obligations may apply to AI-generated media depending on audience — this belongs as an explicit field in each channel playbook, not as an assumption.
