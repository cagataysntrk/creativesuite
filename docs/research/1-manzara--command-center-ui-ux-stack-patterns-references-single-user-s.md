## Özet

As of August 2026 the "default" React stack has consolidated hard, which is good news for a solo operator. Next.js 16.3 (Aug 3, 2026) is the mainstream choice: Turbopack is the stable default, Cache Components (`use cache`, explicit opt-in caching, dynamic-by-default) replaced the old implicit cache model, and 16.3 added a real client-side router cache plus Instant Navigations and ~90% lower dev memory. React 19.2 with the React Compiler stable and View Transitions ships inside it. TanStack Start is a credible Vite-based alternative but is still Release Candidate (1.168.x line), so Next.js is the lower-risk pick. The biggest 2026 shift for UI kits: shadcn/ui made Base UI the default primitive in July 2026 (Radix still fully supported, React Aria added as a first-class base), and shadcn CLI v4 (March 2026) added `--base`, `--template`, `--preset`, `--dry-run/--diff`, `shadcn info`, `shadcn docs`, `registry:base`/`registry:font` and agent-facing skills — the registry is now the distribution channel for whole design systems. The AI-native UI layer matured too: AI SDK 6 (Dec 22, 2025) introduced the Agent abstraction, `needsApproval` tools for human-in-the-loop, MCP with OAuth/elicitation, and DevTools; Vercel's AI Elements is a shadcn-compatible registry with 29+ components spanning chatbot, code/artifact, voice and — critically for this project — a Workflow/Canvas set built directly on React Flow. That means the chat UI, the tool-call timeline and the agentic pipeline graph can all come from one registry in one design system. For a single user, local-first sync (Electric/PGlite/Yjs) is unwarranted; a local Postgres plus TanStack Query is enough. Watch licences: tldraw and n8n/Dify are not permissive; React Flow, Excalidraw, Motion, GSAP and dnd-kit are free.

<details><summary>Notlar</summary>

**Next.js 16.3** — Cache Components inverts the old model: everything is dynamic unless you mark `use cache`. Migrating from 15 requires the cacheComponents flag and a real migration pass (see /docs/app/guides/migrating-to-cache-components). 16.3 finally adds a client-side router cache + opt-in Instant Navigations and up to 90% less dev-server memory. Monthly security releases (July 2026 fixed 4 HIGH/5 MEDIUM) — keep it patched since you'll expose it on a VPS.

**React 19.2 + React Compiler** — View Transitions land here, which is what you want for gallery→detail and calendar→post morphs. Some older libs still lag on React 19 peer deps; check before adding.

**shadcn/ui + shadcn CLI v4** — CLI v4 adds --base (radix|base-ui), --template (Next.js, Vite, React Router, Astro, TanStack Start, Laravel), --monorepo, --preset (shareable design-system config code), --dry-run/--diff/--view, `shadcn info`, `shadcn docs`. registry:font makes fonts first-class — directly useful for a brand kit. Dynamic server-side registry search added July 2026.

**Base UI** — Radix is NOT deprecated — `shadcn init -b radix` still works and both bases receive updates. shadcn ships an AI skill for progressive Radix→Base UI migration rather than a codemod. React Aria is also a first-class base now. Pick one base and stay on it.

**Radix UI Primitives** — Ecosystem breadth (third-party shadcn blocks) is still Radix-heavy, so expect occasional mixed-base copy-paste friction.

**Tailwind CSS v4** — v4 changed config from JS to CSS; migrating old shadcn v3 code needs the shadcn Tailwind v4 guide. OKLCH colour values are the default in shadcn v4 themes — good for generating accessible brand palettes.

**Vercel AI SDK 6** — Key bits for you: ToolLoopAgent for reusable agents, needsApproval (static or input-predicate) for approve-before-execute, toModelOutput to control what goes back to the model, strict tool validation, unified generateObject/generateText, built-in DevTools showing LLM calls/tokens/timing/raw payloads, generateImage with reference images (inpainting/img2img), and native reranking. Don't confuse Vercel Workflows/Sandbox (hosted, paid) with the SDK itself.

**AI Elements** — The Canvas component is explicitly 'a React Flow-based canvas for building interactive node-based interfaces' and is fully compatible with React Flow props/API, with Node/Edge/Connection/Toolbar/Controls siblings. So you get an agent-pipeline editor without hand-rolling xyflow styling. Because it's shadcn-registry-based, restyling to your brand is a token change, not a fork.

**assistant-ui** — Used in production by Mastra, LangChain, Helicone. If your app is chat-secondary (command center first, chat as one surface), AI Elements is the better fit; if chat is the main surface, assistant-ui saves more work. Exact current version UNVERIFIED.

**CopilotKit + AG-UI protocol** — Strongest when your agents run in Python (LangGraph/CrewAI/Agno) and your UI is React — AG-UI is the wire format between them. If your whole stack is TypeScript + AI SDK 6, `needsApproval` covers most of it and CopilotKit is extra weight.

**LangChain Agent Inbox** — The Accept/Edit/Respond/Ignore quadrant, each toggleable per interrupt, is the cleanest approval vocabulary published anywhere — mirror it for 'approve this post', 'edit caption then approve', 'tell the agent what's wrong', 'skip'. Requires LangSmith API key in its stock config, which is a lock-in smell if you're not on LangGraph.

**React Flow (@xyflow/react)** — Pro is only examples/templates, not features gated in the library — you never need to pay to ship. The Pro Platform itself was open-sourced. For a single user, hand-authored node types + AI Elements styling is enough.

**tldraw SDK** — tldraw's own repo LICENSE is a custom SDK licence, not MIT. Since this is personal/non-commercial 'for now', the Hobby licence is legitimate — but if you ever monetise the suite, you inherit a commercial licence obligation. Excalidraw is the safe substitute.

**Excalidraw** — Less of an 'app platform' than tldraw (weaker custom-shape story), but for moodboard and storyboard scribbles that's fine. Its scene JSON is easy for an agent to generate programmatically.

**ComfyUI (as a node-graph reference and a backend)** — GPL-3.0 matters: linking/embedding its code into your app has copyleft implications — call it over HTTP instead, which is clean. What to steal: queue-with-live-progress-per-node, node output previews inline in the graph, saved workflow JSON as a first-class artifact, and the 'reroute/collapse' affordances. What to avoid: no opinionated defaults, hostile onboarding, no separation between 'author the pipeline' and 'run the pipeline'.

**n8n** — Read docs.n8n.io/sustainable-use-license before building anything you might commercialise. UX to steal: the node inspector side-panel (input JSON | parameters | output JSON side by side) is the single best debugging affordance in the category — replicate it for your agent steps.

**Dify** — Two real restrictions: you may not run a multi-tenant environment (a tenant = one workspace) without written authorisation, and you may not remove/modify Dify branding in the frontend console (applies to web/ dir or web Docker image). Single-user self-hosting is fine. UX to steal: the run-history view that replays a workflow execution node-by-node with inputs/outputs.

**TanStack Query v5** — With Next 16 Cache Components you get server-side caching; Query still earns its place for client-driven mutations, background refetch and job polling. Don't duplicate the same data in Zustand.

**TanStack Table / Virtual** — Both stable as of 2026 (Query, Router, Table, Form, Virtual are all stable; only Start is RC). Virtual supports grid/masonry-ish layouts with measured dynamic heights, which is what a variable-aspect-ratio gallery needs.

**TanStack Start** — Genuinely nicer type-safe routing and no Cache-Components mental model to learn. But for a solo operator, the Next.js ecosystem (AI Elements, AI SDK examples, deployment docs, agent skills) is deeper. Revisit if Start hits stable and you find Next caching painful.

**Zustand** — Handles zombie-child and context-loss pitfalls. Jotai is the better pick only if you have many fine-grained independent atoms (e.g. per-node form fields on a big canvas); for a single-user command center Zustand + URL state (nuqs) covers ~everything. Do not put server data here.

**tRPC v11** — The real argument for tRPC here is if the agent workers are a separate Node process that needs a typed API surface. Otherwise it's a layer you maintain for little gain.

**cmdk** — Composable and unstyled means you can build nested/scoped pages (⌘K → 'Instagram' → 'New post' → pick brand) which is what Raycast does. kbar is the alternative and ships hotkeys/scoping/undo-redo out of the box, but is more opinionated about styling; ninja-keys, scoutbar and kmenu also exist. Prefer cmdk for design control.

**dnd-kit** — Does NOT handle file drops from the OS — use Uppy or the native drop API for uploads. Atlassian's Pragmatic drag-and-drop is faster at Jira scale and does cover file drops, but has a smaller ecosystem; at 50-200 cards both are indistinguishable.

**Pragmatic drag and drop (Atlassian)** — Fewer tutorials and community packages than dnd-kit. Its 'covers all drag-and-drop use cases including file drops' property is the deciding factor for a media-heavy app.

**Schedule-X** — Smaller community than FullCalendar; verify which plugins are MIT before depending on one. i18n/locale support matters for tr-TR week-start (Monday) and Turkish month names.

**FullCalendar** — Non-commercial/OSS licences exist for the premium plugins. Its styling is dated and fights Tailwind; budget time for CSS overrides.

**react-big-calendar** — Fewer features and a more manual DnD story (needs the drag-and-drop addon), but nothing is gated.

**Recharts + shadcn/ui Charts** — ~150kB bundle. Fine for post-performance and pipeline-cost dashboards. Don't also install Tremor — they overlap almost completely (both copy-paste, Tailwind, Recharts underneath).

**Tremor** — 'Show the data, hide the chrome' is the right philosophy for a personal dashboard. Built on Radix, so mixing it into a Base UI project adds a second primitive dependency.

**ECharts / Nivo / visx / Observable Plot** — ECharts is by far the largest bundle and its theming will not match shadcn tokens without work. For a single-user command center this is almost certainly over-engineering.

**yet-another-react-lightbox** — Pair with react-photo-album (same author) for justified/masonry grids, and TanStack Virtual if the library exceeds a few thousand assets. PhotoSwipe is the framework-agnostic alternative with better mobile gestures.

**Vidstack Player** — Storyboard/thumbnail-on-scrub needs a VTT sprite you generate with ffmpeg at ingest time — build that into the asset pipeline. Media Chrome (also MIT, from Mux) is the alternative if you prefer pure web components.

**Uppy** — You must run @uppy/companion yourself to enable Google Drive/Dropbox imports. The built-in image editor gives you free crop-to-aspect-ratio (1:1, 4:5, 9:16) which is exactly the Instagram/Reels workflow.

**Motion (formerly Framer Motion)** — animateView() became free in the core library in 2026 and papers over the View Transition API's rough edges — use it for gallery→detail and list→canvas transitions. Restraint rule: animate layout and presence, never decorate; keep durations 150-250ms for UI, honour prefers-reduced-motion.

**GSAP** — One real restriction survives: you may not use GSAP inside a no-code visual animation builder that competes with Webflow's animation capabilities. Building an internal deck/Reels animator for yourself is fine; shipping a public 'animate without code' tool is not.

**Lenis** — Hijacked scroll breaks scroll-anchoring, browser find-in-page feel and fast scanning of long asset grids. This is a marketing-site library, not an app library.

**PGlite** — Pre-1.0, single-user mode, no concurrent connections. For a self-hosted single-user app a real Postgres in Docker is simpler and lets you use pgvector for brand/product knowledge retrieval without WASM caveats.

**Electric (ElectricSQL sync engine)** — Revisit only if you want the command center to work offline on a laptop AND a phone with conflict-free edits. Until then it's an extra service, extra replication slot, and extra failure mode.

**TinyBase / Dexie / Yjs** — The one legitimate local-first use here is draft autosave resilience: keep unsent post drafts in IndexedDB so a browser crash never loses a caption. That's ~30 lines with Dexie, not an architecture.

**Tauri v2** — Tauri 2.x apps are reported ~96% smaller than equivalent Electron 34.x builds. The real reasons to wrap: a Raycast-style global hotkey that summons the command palette from anywhere, drag-out of generated assets to Finder/Explorer, and local ffmpeg/ComfyUI process management. Requires learning some Rust; Electron is the escape hatch if that stalls you.

**Streamlit / Gradio** — Neither can deliver the keyboard-first, dense, branded UX you're describing — rerun-on-every-interaction is the wrong model for a canvas + calendar app. Keep them for one-off model-tuning scratchpads.

**Raycast** — Linux support is the blocker for using it as your actual launcher (you're on Linux). Replicate the interaction model inside your web app with cmdk instead.

**Linear** — Its real lesson is latency discipline: every interaction resolves locally first. For an agentic app where model calls take 10-40s, that means immediately showing a pending card with a live status, never a blocking spinner.

**Vercel dashboard / Retool / Superhuman / Cursor / Notion / Figma / Runway / Later / Postiz** — What to steal from each: Vercel dashboard — deployment log streaming as the model for agent run logs. Retool — resizable inspector panels and the 'query returns → bind to component' mental model. Superhuman — split-second keyboard triage and the 'command palette teaches you shortcuts' loop. Cursor — inline diff-accept/reject as the pattern for AI-edited copy. Notion — slash-menu block insertion for the post composer. Figma — multiplayer-grade canvas performance, and Variables as the model for brand tokens. Runway/Krea — generation queue with per-job thumbnails and re-roll/variation buttons. Later — visual Instagram grid preview so you see feed aesthetics before posting. Postiz — per-channel post preview tabs rendering the same content in each network's real chrome. AGPL-3.0 on Postiz means if you expose a modified copy over a network to others you must publish source; personal single-user self-hosting is unaffected.

### Riskler

- Next.js 16's Cache Components inverts the caching default (dynamic unless `use cache`), so any tutorial, blog post or agent-generated code written for Next 13-15 will produce subtly wrong caching behaviour — plan a deliberate migration/verification pass and pin your AGENTS.md to the 16.x docs.
- shadcn's July 2026 switch to Base UI means the large body of third-party shadcn blocks and templates on the internet is still Radix-based; mixing bases pulls in two primitive libraries and produces inconsistent focus/portal/a11y behaviour. Pick one base at init and enforce it.
- tldraw, n8n and Dify are all source-available rather than OSI open source: tldraw needs a paid commercial licence or accepts a watermark, n8n's Sustainable Use License forbids offering it as a service, and Dify forbids multi-tenant operation and branding removal. Personal single-user self-hosting is fine today, but each becomes a licence problem the moment 'not a product to sell (for now)' changes.
- Postiz is AGPL-3.0. Self-hosting for yourself is unaffected, but if you ever expose a modified Postiz — or a derivative that links its code — over a network to other users, you owe them the source. Keep it as a separate service you call over HTTP rather than forking it into the monorepo.
- ComfyUI is GPL-3.0. Calling it over its HTTP/WebSocket API is clean; vendoring or linking its Python into your own codebase drags copyleft into your suite.
- TanStack Start is still Release Candidate in mid-2026; betting the command center on it means accepting API churn and a much thinner supply of AI-UI integrations (AI Elements, AI SDK examples and most shadcn templates assume Next.js).
- PGlite is pre-1.0 with single-user-mode limitations; using it as the production database for anything you care about risks data-loss and migration pain that a Docker Postgres simply does not have.
- GSAP is free but retains a prohibition on using it inside no-code visual animation builders that compete with Webflow — if the Creative Suite ever grows a public 'animate your post without code' feature, that clause bites.
- An agentic command center hides latency badly: model and render calls take 10-60s, and a naive request/response UI will feel broken. Without an explicit job/queue model (pending cards, per-step progress, resumable runs, cancel), the UX quality will collapse regardless of how good the component library is.
- Media-heavy galleries degrade fast: unvirtualised grids of a few thousand generated images will jank on any laptop. Commit to TanStack Virtual plus ffmpeg-generated thumbnails and VTT scrub sprites at ingest time, not as a later optimisation.
- Turkish-language content adds concrete correctness risks that are easy to miss: dotted/dotless i casing (İ/ı) breaks naive toLowerCase/toUpperCase and search matching, Turkish characters inflate byte counts against per-network character limits, and Europe/Istanbul is UTC+3 year-round with no DST — mishandling any of these silently mis-schedules or truncates posts.
- Depending on Vercel-owned building blocks (Next.js, AI SDK, AI Elements, and now Tremor) concentrates a lot of strategic risk in one vendor's roadmap, even though every individual piece is open source and self-hostable today.
