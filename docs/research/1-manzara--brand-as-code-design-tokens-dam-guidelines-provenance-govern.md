## Özet

The "brand as code" stack finally has a real standard underneath it. The W3C Design Tokens Community Group shipped its first stable Design Tokens Format Module (2025.10) on 2025-10-28 — JSON, `$value`/`$type`/`$description`, groups, `{alias}` references, composite types (typography, shadow, border, gradient, transition) — and it is now implemented by Style Dictionary v5, Terrazzo, Tokens Studio, Penpot, Figma and Sketch. It is still a Community Group report, not a W3C Recommendation, and the drafts site carries a loud "do not implement this draft" warning, so pin to the 2025.10 tag, not `drafts`. For a solo operator the free/OSS spine is: hand-authored `.tokens.json` in git → Style Dictionary v5 (Apache-2.0, needs Node 22+) → CSS vars, Tailwind theme, JSON for prompt templates and slide themes. Terrazzo (MIT) is the lighter alternative. Figma's Variables REST API is Enterprise-only, so Penpot (MPL-2.0, native DTCG, self-hostable, has plugin API + MCP) is the realistic free design-tool leg. The commercial doc layer thinned out: Specify is dead, Backlight died June 2025, Fractal archived March 2026, Pattern Lab archived May 2026. Survivors worth free-tier use are Supernova (free tier, SDK + MCP) and zeroheight (free 1 editor, MCP but API is Enterprise). For DAM at n=1, Directus (free self-host under $5M revenue) or plain S3-compatible storage + sidecar JSON beats a real DAM. Provenance stopped being optional: EU AI Act Art. 50 applies from 2026-08-02 and requires machine-readable marking of synthetic output; C2PA + IPTC `digitalSourceType=trainedAlgorithmicMedia` is the practical implementation, both writable free via c2patool and ExifTool. For retrieval, markdown + ripgrep is genuinely sufficient at this scale; add LanceDB or sqlite-vec only when the corpus outgrows a single prompt.

**DTCG Design Tokens Format Module 2025.10** — First stable version published 2025-10-28. It is a W3C Community Group report, NOT a W3C Standard and not on the Standards Track. The living draft at designtokens.org/TR/drafts/ explicitly says 'Do not attempt to implement this version'. Token types: color, dimension (px|rem only), fontFamily, fontWeight, duration, cubicBezier, number + composites strokeStyle, border, transition, shadow, gradient, typography. Recommended extension .tokens or .tokens.json, MIME application/design-tokens+json. 2025.10 adds $deprecated, $extends group inheritance and $root.

**DTCG Color Module / Resolver Module** — UNVERIFIED whether Resolver has reached a stable dated version; the drafts index lists Format, Color and Resolver as modules but only 2025.10 is marked stable. Jina Anne and Val Head stepped back as co-chairs in June 2026, so cadence may slow.

**Style Dictionary v5** — Latest is the 5.5.x line (v5.5.1 is the newest release on GitHub). v5 REQUIRES Node >= 22.0.0. Breaking vs v4: references only resolve to real token leaf nodes with $value/$type (no referencing groups), and reference syntax is locked to {a.b} DTCG style — no custom brace/separator characters. Write a custom format to emit a 'brand-facts.json' for prompt injection; that is the trick that makes tokens agent-consumable.

**@tokens-studio/sd-transforms** — Version pinning matters: sd-transforms >=1.0.0 pairs with Style Dictionary >=4.0.0. Confirm a 5.x-compatible line before wiring it in.

**Terrazzo (formerly Cobalt / cobalt-ui)** — Renamed from Cobalt UI 2.0. ~443 stars, smaller ecosystem than Style Dictionary, fewer platform outputs (no Android/Compose/Flutter). Its strict parser catching malformed tokens is genuinely useful as a CI gate.

**Tokens Studio for Figma + Tokens Studio Platform** — Multi-file / folder sync (the mode you need if you want one file per token set in git) requires a Pro-level licence. Its JSON is a near-DTCG dialect, not pure DTCG — hence sd-transforms. Git sync writes directly to a branch, which is nice but ties your brand repo to a paid SaaS.

**Penpot** — First design tool to fully adopt DTCG, built in collaboration with Tokens Studio. Round-trips token JSON without conversion, so git stays the source of truth and Penpot is just a visual editor over it. Heavier to self-host than a static site (needs Postgres + Redis).

**Figma Variables REST API** — Both read and write endpoints are Enterprise-gated; guests cannot use it. Community has been asking for lower-tier access for years with no change. The Tokens Studio plugin remains the non-Enterprise escape hatch.

**Figma Dev Mode MCP server** — Pricing model explicitly not final. Do not architect a pipeline whose critical path is a beta MCP with an announced future price.

**Salesforce Theo** — UNVERIFIED current maintenance status; listed only so you can recognise and reject it in old tutorials.

**Specify** — Cautionary tale #1 for the whole category: do not put your brand's source of truth inside a VC-funded token SaaS. Same lesson as Backlight.

**Backlight.dev** — Cautionary tale #2.

**Supernova** — 1,000 credits/month and 2 AI contexts are the real limits — fine for one person. Risk: it becomes the source of truth and you are back in SaaS lock-in. Use it as a read-only projection of your git repo, never the master copy.

**zeroheight** — Note the free MCP server: 500 calls/month is enough for personal agent lookups. Style Dictionary v5 is what their own token automation migrated to, which is a good signal for your own pipeline choice.

**Knapsack** — Minimum-seat pricing means the floor is thousands of dollars a year even if you are one person.

**Storybook** — Static export is a plain folder — trivially self-hosted next to your token docs. Combine with Style Dictionary to render live token tables.

**Astro Starlight** — Starlight 0.39 shipped May 2026 (flexible autogenerated sidebars, better multilingual). Still pre-1.0, so expect minor breaking changes. Turkish-language site is a first-class case via its i18n routing.

**Fractal (frctl/fractal)** — Also flagged by adopters (e.g. USWDS) for dependency vulnerabilities before archival. Fork only if you must.

**Pattern Lab (patternlab-node)** — Read Brad Frost's Atomic Design book for the ideas; do not run the tool.

**cofoundy/brand-skills (brand.yaml)** — This is the single most directly reusable prior art for your repo. Even if you never run the skills, copy the file layout: a YAML manifest as the queryable HEAD plus one markdown artifact per brand dimension is exactly the shape agents consume well. Note it does NOT cover visual tokens — pair it with a DTCG tokens file.

**llms.txt** — Not a ratified standard and contested as an SEO/AI-visibility tactic. For your INTERNAL pipeline the equivalent is an AGENTS.md / brand-context.md in the repo root that your agents read directly — that is what actually matters.

**southleft/design-systems-mcp** — UNVERIFIED licence and maintenance. It serves other people's design systems; your own brand still needs its own context file.

**kenneives/design-token-bridge-mcp** — Small, single-author project. UNVERIFIED licence, stars, maintenance. Mentioned for completeness.

**Directus** — NOT OSI open source — it is source-available. You are free at your scale, but understand you are relying on a revenue-threshold grant, not a permissive licence. Its killer feature for you: arbitrary metadata fields on files + filterable REST queries = a DAM with brand-specific tags (campaign, product, channel, ai_generated) without running a real DAM.

**Payload CMS** — Acquired by Figma in June 2025; Payload Cloud no longer exists as of mid-2026, so self-hosting is the path. Config-as-code means your asset schema is versioned alongside your brand tokens — a real advantage for 'brand as code'. Downside: it wants to be your app, not a sidecar service.

**Strapi** — UNVERIFIED: current major version and precisely which features moved to EE in 2026. Its Media Library has no real taxonomy/tagging depth out of the box.

**Pimcore** — Its channel-specific output format generation (auto-derivatives per platform) is the one feature you would actually miss. You can replicate it with imgproxy or sharp in a script for a fraction of the operational cost.

**ResourceSpace** — UNVERIFIED: precise licence per component and current version. Its metadata field configuration is far richer than any headless CMS media library, which matters if you plan thousands of generated assets.

**Phraseanet** — AGPLv3 matters if you ever expose a modified instance over a network — you would owe source. Fine for purely personal use. UNVERIFIED: current API version and Docker support quality.

**Immich** — v3.0.0 stable shipped 2026-07-01 (HLS + real-time transcoding, workflow automation previews, non-destructive mobile editing). AGPL-3.0. It is a PHOTO app, not a DAM: no font files, no vector logos, no versioning of brand assets. Best used as a secondary index over generated output, with Directus/git as the authoritative brand store.

**PhotoPrism** — UNVERIFIED: which exact features are membership-gated in 2026 and whether the REST API is officially supported for third-party clients. Feature gating in an AGPL project is a yellow flag for an automation-first workflow.

**Nextcloud** — If you already run Nextcloud, its systemtags + WebDAV is a zero-additional-service DAM. If you do not, do not stand it up for this.

**MinIO** — OpenMaxIO fork stalled and is abandoned as of February 2026; a newer pgsty fork exists but carries the same AGPL exposure. Reported to be in maintenance mode. If you want S3 semantics locally, Garage (AGPL but healthy) or SeaweedFS (Apache-2.0) are safer; for a solo operator Cloudflare R2 is cheaper than the ops time.

**Razuna / OpenDAM-class projects** — Listed only so you can stop chasing them. 'Damsel/OpenDAM' in particular did not resolve to a maintained project — treat as vapour.

**C2PA specification (Content Credentials)** — Latest spec version listed is 2.4 (2.3 is the version with downloadable PDFs). The AI Act never NAMES C2PA — it is technology-neutral — but the Commission's draft Code of Practice on Transparency names Content Credentials by example. The certificate story is the real friction: self-signed manifests are readable but not trusted.

**c2patool / c2pa-rs** — Ships a built-in dev key/cert that emits a warning — never ship those. For personal use a self-signed cert is fine and still satisfies 'machine-readable marking'; buy a real cert only if you need third-party verification. Sibling repo contentauth/c2pa-attacks exists for testing robustness — worth knowing that C2PA is strippable by any re-encode, which is why you should ALSO write IPTC/XMP.

**EU AI Act Article 50 (transparency obligations)** — CRITICAL nuance for you: the primary marking duty in Art. 50(2) falls on PROVIDERS of generative AI systems (the model vendors), not on you as a downstream user. Your exposure is the DEPLOYER duty around deepfakes and the general disclosure expectation. Exemptions cover assistive editing that does not substantially alter input, artistic/satirical/fictional works (limited disclosure only), AI text under human editorial review, and cases obvious to a natural person. Turkey is not in the EU, but if your Turkish-language content reaches people in the EU the obligation attaches. Marking cost is near zero — just do it. This is legal information, not legal advice; get a lawyer if you commercialise.

**IPTC Photo Metadata Standard 2025.1** — The URI is http://cv.iptc.org/newscodes/digitalsourcetype/trainedAlgorithmicMedia. Version 2025.1 (published November 2025) adds four AI properties: AI Prompt Information, AI Prompt Writer Name, AI System Used, AI System Version Used — meaning you can store the exact generation prompt IN the file, which is superb for a brand archive you later want to search or reproduce.

**ExifTool** — Supports the new IPTC 2025.1 AI properties since version 13.40 (released 2025-10-24) — pin at least that version. Example: exiftool -XMP-iptcExt:DigitalSourceType=https://cv.iptc.org/newscodes/digitalsourcetype/trainedAlgorithmicMedia image.jpg . Run ExifTool AFTER c2patool, and verify the C2PA manifest still validates — metadata writes can invalidate signatures.

**Google Fonts + Google Fonts Developer API** — For Turkish you need the latin-ext subset (covers ğ Ğ ş Ş ı İ ç ö ü and the dotted/dotless i pair) — filter the API by subset=latin-ext and REJECT families that only ship 'latin'. Verify the dotless ı and dotted İ specifically; some families include latin-ext but render İ poorly. Strong Turkish-covering families: Roboto, Inter, Source Sans 3, Noto Sans, IBM Plex Sans, Manrope, Figtree, Lora, Merriweather. Self-host the actual .woff2 in your repo — do not hotlink fonts.googleapis.com from generated assets.

**Fontsource** — Per-family packages expose subset-specific files (e.g. latin-ext) so you ship only what Turkish needs. UNVERIFIED from the homepage: exact subsetting granularity and licence listing per family — check the individual font page. Pair with fonttools/pyftsubset if you need to subset further for video render pipelines.

**SIL Open Font License 1.1** — Two obligations that matter for automation: (1) you may not sell the FONT itself standalone; (2) if you MODIFY a font (subsetting counts as modification in some readings) you must not use the Reserved Font Name. Rename subsetted variants. Apache-2.0 fonts (Roboto and friends) have no RFN clause and are the most frictionless.

**Adobe Fonts** — UNVERIFIED - the Adobe licensing page timed out during this research. Historically Adobe Fonts does NOT permit extracting font files for server-side automated generation, embedding in applications, or redistributing files. Assume you cannot use them in an automated render farm until you read the current terms yourself. This is exactly why the OFL route is the right one.

**LanceDB** — The multimodal story is the differentiator for a creative suite: you can put brand docs AND asset embeddings in the same store. Downside: fast-moving, pre-1.0-feeling API surface in places.

**sqlite-vec** — IMPORTANT: still pre-v1 / alpha — current line is 0.1.10-alpha.x and the README warns to expect breaking changes to the SQL API and storage format before v1.0. A GitHub issue explicitly asks whether it is still maintained after a half-year gap, though there is 2026 issue activity. Mozilla Builders project with Fly.io/Turso sponsorship. Do not build anything load-bearing on the storage format yet.

**Chroma** — Best for prototyping the retrieval layer before committing. Now has object-storage backend and collection forking. Releases ship weekly on Mondays — pin your version.

**Qdrant (+ Qdrant Edge)** — Its payload filtering is the best in class, which matters if you want 'find brand assets where channel=instagram AND product=X AND similar-to Y'. If you ever DO need that query shape, Qdrant is the upgrade path.

**pgvector** — Widely argued to be the pragmatic default for RAG in 2026: vector-enabled general databases absorbed the workload of vector-first databases for everyone below billion-scale. Your scale is thousands of chunks — this is dramatically over-provisioned already.

**txtai** — Batteries-included is both the appeal and the risk — it pulls in a lot of ML surface area for what may be a small corpus.

**Marqo** — Strong option specifically if you want image search over your generated-asset archive WITHOUT writing embedding code. Competes directly with LanceDB for that job; LanceDB is lighter, Marqo is more turnkey.

**Plain markdown + ripgrep + a generated index (the null option)** — The honest answer to question 7: yes, plain markdown plus a good index is sufficient, and it stays sufficient until your generated-asset ARCHIVE (not your docs) needs similarity search over images. Build the token pipeline and provenance stamping first; add LanceDB when the asset count crosses a few thousand. Ripgrep gives exact-match recall that embeddings are actually WORSE at for things like hex codes, product names and Turkish brand terms.

### Riskler

- EU AI Act Article 50 became applicable on 2 August 2026 — twelve days before today — so this is live law, not a future deadline; the primary marking duty falls on PROVIDERS of generative systems rather than on you as a downstream user, and there are exemptions for artistic/satirical/fictional work and for AI text under human editorial review, but the deployer disclosure duty around deepfakes can attach to you if your Turkish-language content reaches people in the EU. Penalties for transparency violations start at EUR 7.5M or 1.5% of global turnover. This is legal information, not legal advice.
- C2PA manifests are strippable: any re-encode, screenshot, or social-platform transcode destroys the signature, and most platforms re-encode uploads. Never rely on C2PA alone — always also write IPTC/XMP digitalSourceType, and understand that neither survives a screenshot. Trusted (non-self-signed) C2PA signing also requires an X.509 certificate from a recognised CA whose cost this research could not verify.
- The DTCG spec is a W3C Community Group report, NOT a W3C Standard and not on the Standards Track, and its own drafts page says 'Do not attempt to implement this version'. Both long-time co-chairs stepped back in June 2026. Pin to the dated 2025.10 tag and expect the Resolver/Color modules to move under you.
- Licence traps in the DAM layer: Directus is source-available (BSL 1.1 moving to the Monospace Sustainable Core License with v12) and your free use depends on staying under a $5M revenue / 50-employee grant rather than on a permissive licence; Pimcore uses its own Pimcore Open Core License; Immich, PhotoPrism, Phraseanet, Nextcloud and MinIO are all AGPL-3.0, which creates source-disclosure obligations if you ever expose a modified instance over a network. Only Payload (MIT), Style Dictionary (Apache-2.0), Terrazzo (MIT) and Penpot (MPL-2.0) are cleanly permissive.
- MinIO actively degraded its own community edition — admin UI removed in June 2025, free Docker images withdrawn, reported maintenance mode — and the OpenMaxIO community fork is abandoned as of February 2026. Do not build your asset storage on it; the same open-core-rug-pull pattern is worth watching for in Directus and Pimcore.
- sqlite-vec is still pre-v1 alpha (0.1.10-alpha.x) with documented intent to break both the SQL API and the on-disk storage format before 1.0, and there is an open issue questioning whether it is maintained. Do not make it the only copy of anything.
- SaaS mortality in this exact category is unusually high: Specify shut down, Backlight shut down, Fractal archived March 2026, Pattern Lab archived May 2026. Any architecture where a hosted product holds the canonical brand data has a demonstrated failure mode. Keep git as master and treat all platforms as replaceable renderers.
- Figma's Dev Mode MCP is explicitly free only 'during beta' with a stated intent to become usage-based paid, and free/View seats get six tool calls per MONTH — do not put it on the critical path of an automated pipeline.
- Font licensing is the quietest legal risk in automated generation: OFL forbids selling the font standalone and forbids reusing a Reserved Font Name on a modified (including subsetted) font, and Adobe Fonts almost certainly prohibits the server-side extraction and rendering an automated pipeline requires. Verify per-family, and verify Turkish dotless-ı/dotted-İ rendering separately from the latin-ext subset flag.
- Turkey is outside the EU, so EU AI Act obligations attach through audience reach rather than establishment; separately, Turkish data-protection (KVKK) and any Turkish-specific advertising-disclosure rules for AI-generated marketing content were NOT researched here and should be checked before publishing at scale.
- Over-engineering is the most likely actual failure: a vector database, a full DAM, a design-token SaaS and a documentation platform for one person's brand is four services to maintain instead of one repo. Every item marked ADOPT above that is not git, Style Dictionary, ExifTool or markdown should be justified by a concrete failure of the simpler option first.
