## Özet

The 2026 landscape splits into three camps, and only one of them produces decks that read as "a design agency made this."

Camp 1 — code-first web decks (Slidev, Marp, reveal.js, Spectacle, Typst+Touying). Theming depth is effectively unlimited because it is just CSS/Vue/Typst. These win on looking designed. Their fatal flaw for B2B sales is confirmed: Slidev's PPTX export rasterises every slide ("text will not be selectable"), and Marp CLI's default PPTX is background images; its `--pptx-editable` flag is experimental, needs LibreOffice Impress, loses fidelity and drops speaker notes. So code-first alone cannot satisfy "Upcytech can still edit it" in PowerPoint.

Camp 2 — native-format generators (PptxGenJS MIT, python-pptx, Google Slides API). These produce genuinely editable output with native shapes, tables and charts, but you must author the design yourself; there is no AI layout intelligence and PPTX cannot embed fonts.

Camp 3 — AI deck products. Real, usable APIs in 2026: Gamma (GA, credit-metered, Pro/Ultra/Teams/Business only), Presentations.ai (REST + webhooks), Plus AI (Presentation Agent API + MCP), SlideSpeak. Canva Connect has the best brand fidelity via Brand Templates + Autofill but requires **Canva Enterprise**, which realistically excludes a solo operator. Pitch still says "API coming soon". Beautiful.ai advertises no API. OSS AI generators are real but uneven: Presenton (Apache-2.0, 9.5k stars, HTML+Tailwind custom templates, self-host Docker, editable PPTX export) is the only one I'd trust in production; PPTAgent/DeepPresenter (MIT, 4.9k stars, ACL 2026) is research-grade with heavy setup.

The winning architecture is not "pick a product" — it is one deck IR (JSON) with a constrained layout enum, rendered twice: HTML/React → Playwright PDF + live web deck, and the same IR → PptxGenJS for the editable native file. That single pipeline serves LinkedIn document posts, interactive links and .pptx from one source of truth.

### Öneriler

- ARCHITECTURE — build a Deck IR, not a deck generator. Define `deck.schema.json` (Zod in the Next.js command center): `{ meta, brand_ref, slides: [{ layout: LayoutEnum, slots: {...}, data_binding?, notes_tr }] }`. The LLM NEVER emits HTML, CSS, coordinates or free-form design — it only picks a `layout` from a closed enum and fills named slots with text under hard character caps. This one constraint is what separates 'looks like an agency made it' from 'generic AI slides', because every possible output was designed by you in advance. Everything downstream is deterministic rendering.
- RENDER THE SAME IR TWICE — this is the answer to your question 7 (one pipeline, three outputs). Renderer A: React slide components on a fixed 1920x1080 canvas inside the Next.js app → Playwright page.pdf() for the LinkedIn document post, page.screenshot() at 2x for thumbnails, and the same route served live as the interactive web deck at a per-prospect URL. Renderer B: a PptxGenJS module where each LayoutEnum member has a hand-written function emitting native text boxes, shapes and charts positioned from the SAME token file. You write each layout twice — that is the honest cost, roughly 2-4 hours per layout — and in exchange you get agency-grade visuals AND a genuinely editable .pptx that no product on the market gives you at $0.
- SHIP 12-16 LAYOUTS, NOT 50. Concretely for your use cases: cover-with-prospect-logo, agenda, problem-statement (big type, one line), before/after split, three-pillar, single-metric-hero, metric-trio, chart-full-bleed, chart-with-callout, architecture-diagram (D2/Mermaid slot), product-screenshot-device-frame, quote/testimonial, pricing-table, timeline/roadmap, team/about-Upcytech, CTA-with-next-steps. Every layout must define its own overflow behaviour: if content exceeds the slot's character cap, AUTO-SPLIT into a second slide. Never shrink type to fit — auto-shrinking text is the #1 visual tell of machine-generated decks.
- DESIGN TOKENS AS THE SINGLE SOURCE. One `brand/tokens.json` in the git repo → generated three ways: CSS custom properties for the HTML lane, a PptxGenJS theme object (colours as hex without '#', sizes in points not px) for the pptx lane, and a theme JSON for Mermaid --cssFile / D2 / ECharts palettes. Include a 1920x1080 12-column grid with a 96px margin and 32px gutter, an 8px baseline, and a modular type scale (e.g. 1.25 ratio: 20/25/31/39/49/61/76). Rule enforced in code: max 3 type sizes and max 2 weights per slide.
- FREE LANE (target ~$0/deck): local LLM via Ollama or a free-tier API → deck IR → React render → Playwright PDF + live web deck → PptxGenJS editable .pptx → LibreOffice headless renders that .pptx back to PDF → automated pixel diff against the HTML PDF to catch layout breakage before the prospect sees it. Charts via ECharts SSR to SVG (Apache-2.0, crisp at any zoom); diagrams via D2 (MPL-2.0) or Mermaid CLI (MIT). Optionally add self-hosted Presenton (Apache-2.0, HTML+Tailwind templates, local Ollama provider) as the AI drafting layer. Total marginal cost: electricity.
- PREMIUM LANE (target $0.30-$2.00/deck): swap ONLY the intelligence and the imagery, never the renderer. Frontier LLM for the outline, layout selection and Turkish copy (~$0.10-0.60/deck); premium image generation for hero visuals; optionally Brandfetch/Clearbit for the prospect's logo and brand colour on the cover slide. Keep your own renderer. This is the crucial cost-model insight: paying more should buy better WORDS and better PICTURES, not a different design system — otherwise your premium decks and free decks look like they came from two different companies.
- COST ESTIMATOR (your mandatory pre-run requirement). Model it per-step: LLM tokens (estimate from slide count × ~400 output tokens + context), image count × per-image price, and for vendor lanes model CREDITS not decks — Gamma is confirmed at 1-3 credits/card plus 2-125 credits/image depending on model tier, so a 12-slide deck with 6 premium images spans roughly 36-486 credits, a >10x range. Show the user a min/expected/max band, never a single number, and let them cap image tier before the run.
- DON'T BUILD ON CANVA — but do steal its model. Canva Connect Autofill is confirmed Enterprise-only, so it's out for a solo operator. However 'hand-design the template, let the API only pour data in' is exactly right, and PptxGenJS masters + defineLayout gives you the same discipline for free. Revisit Canva only if a client already has Enterprise and wants decks inside their own workspace.
- USE GAMMA'S API AS A DRAFTING TOOL, NOT A DELIVERY TOOL. It's confirmed GA with real theme control (GET /themes → themeId), pdf/pptx/png export and live editable output. Good for: generating 5 rough structural variants of a pitch in 60 seconds so you can pick a narrative. Bad for: the artifact the prospect actually receives, because that deck will look like Gamma, not like Upcytech. Requires Pro/Ultra/Teams/Business.
- DATA-DRIVEN SLIDES (question 7): put a `data_binding` field in the IR — `{ source: 'products/rtblab/pricing.json', query: '...' }` — resolved at generation time from the git repo's own product/pricing files and any live Postgres/analytics source. Snapshot the resolved values INTO the generated deck artifact and commit it alongside, so a deck you sent in March still shows March's numbers when a prospect asks about it in June. Never let a delivered deck re-query live data.
- TURKISH TYPOGRAPHY IS A REAL BLOCKER — check it first. Your brand font must carry full Latin Extended-A: dotless ı, dotted İ, ş, ğ, ç, ö, ü. Many display and AI-favoured fonts ship İ but not ı, which produces silently broken Turkish. Test the string 'İstanbul'da yazılım çözümleri: ığüşöç ĞÜŞÖÇ' in every renderer before adopting a font. Separately: PPTX cannot embed fonts and PptxGenJS cannot add them, so define a metric-compatible fallback (a Microsoft-bundled font) for the editable lane and treat the PDF as the canonical visual artifact.
- APPROVAL QUEUE MECHANICS (matches your staged-publishing requirement). Each pipeline run writes to `output/decks/<prospect>/<date>/` containing: deck.json (the IR), deck.pdf, deck.pptx, slides/*.png, and cost.json (estimated vs actual). The Next.js command center shows the PNG contact sheet for approval; approving promotes the artifacts and git-commits them. Because the IR is committed too, regenerating a deck for a similar prospect is a copy-and-edit of the IR, not a fresh LLM run — that alone will cut your marginal cost dramatically over the first twenty decks.
- STEAL PPTAgent'S TWO IDEAS WITHOUT RUNNING PPTAgent. (1) Its reference-deck analysis — extract functional slide types and content schemas from decks you admire, and let that define your layout enum. (2) PPTEval's three-axis scoring (Content / Design / Coherence) — run it, or a simpler LLM-as-judge version, as a CI gate on generated decks so quality regressions surface before a prospect meeting rather than during one.
- SEQUENCING. Week 1: tokens.json + 4 layouts (cover, three-pillar, chart, CTA) in React + PptxGenJS + the LibreOffice visual-diff harness — prove the dual-renderer thesis on a real deck end to end. Week 2: expand to 12-16 layouts and add the ECharts/D2 slots. Week 3: bolt on the LLM IR-generation step with the closed layout enum and the cost estimator. Only then evaluate Presenton self-hosted or Gamma as optional accelerators. Do NOT start by evaluating AI deck products — you'll spend three weeks on trials and end up with decks that look like everyone else's.


### Riskler

- THE HEADLINE TRAP: every code-first framework's PPTX export is rasterised. Slidev's docs state outright that slides export as images and 'the text will not be selectable'. Marp's default --pptx is background images, and its --pptx-editable escape hatch is experimental, needs LibreOffice Impress, explicitly warns of 'lower slide reproducibility', and drops presenter notes. If you pick a code-first framework and assume you'll 'just export to pptx later', your editability requirement fails at the worst possible moment.
- FONT EMBEDDING IN PPTX. PowerPoint files do not carry your brand font unless PowerPoint itself embeds it, and PptxGenJS has no mechanism to do so. A prospect opening your .pptx without your font installed sees substituted type and reflowed text boxes. Mitigate with a metric-compatible fallback in the pptx lane and by treating PDF as canonical — but never promise a prospect the .pptx will look identical.
- TURKISH GLYPH COVERAGE. Fonts missing dotless ı or dotted İ fail silently and unprofessionally in Turkish sales material. This must be a gate in font selection, not a bug discovered by a client.
- CANVA ENTERPRISE GATE. The autofill endpoint confirmedly requires Canva Enterprise membership; paid plans get only limited trial functionality during integration development. Any architecture assuming Canva Brand Templates is dead on arrival for a solo operator. Also note brand template IDs migrated to a new format in Sept 2025 with only a 6-month legacy window, and chart/sheet/video autofill are preview features 'subject to unannounced changes'.
- GAMMA CREDIT COST VARIANCE IS >10x. Confirmed ranges: 1-3 credits/card, and images from 2 (standard) to 125 (ultra) credits each. A pre-run estimate that shows one number will be wrong most of the time. Gamma's plan USD prices and monthly credit allowances could not be verified (pricing page 403), so per-credit cost in dollars is currently unknown to you.
- UNPUBLISHED GAMMA RATE LIMITS. The docs expose x-ratelimit-remaining-burst / -remaining / -remaining-daily headers but publish no numbers. A batch job generating decks for a prospect list can hit an undocumented ceiling mid-run; you must build adaptive polling off those headers rather than fixed concurrency.
- QUICKCHART SELF-HOST IS AGPL-3.0. Internal use is fine, but if deck generation ever becomes a feature Upcytech's customers touch over a network, AGPL §13 obligations attach. ECharts (Apache-2.0) sidesteps this entirely — prefer it. Similarly note D2 is MPL-2.0 (file-level copyleft, fine for binary use, relevant if you fork).
- GOOGLE SLIDES API BILLING CHANGE. Confirmed in the official limits page: exceeding quota is 'planned to incur charges to your Google Cloud billing account starting later in 2026.' Free today, not necessarily free by year-end. Current quotas: 600 writes/min/project, 60/min/user — a batch deck job is write-heavy and will hit the per-user limit faster than you'd expect.
- GOOGLE SLIDES CANNOT CREATE OR EDIT THEMES/MASTERS via API. Your only brand path is hand-building a master deck in the UI and Drive-copying it per prospect. That's workable but means the design lives outside git — breaking your git-backed single-source-of-truth principle.
- PRESENTON IS PRE-1.0 (release notes read v0.9.3-beta) and its docs maintain a separate feature-availability matrix for self-hosted vs cloud. Features you evaluate on the cloud demo may not exist in the Docker image you self-host. Verify against that matrix before building on it.
- PPTAGENT SETUP BURDEN. Windows unsupported, Docker sandbox required, strongly recommends a fine-tuned DeepPresenter model, optional Tavily/MinerU dependencies. Research-grade. Budget days, not hours, and expect to be maintaining it yourself.
- DUAL-RENDERER MAINTENANCE DEBT — the honest cost of my own recommendation. Every layout must be implemented twice (React and PptxGenJS) and they will drift. Mitigate with the LibreOffice-render-and-pixel-diff harness in CI, and by capping the layout catalog at 12-16. If you let it grow to 40 layouts you will abandon the pptx lane within a quarter.
- 'AI SLOP' IS A BRAND RISK IN B2B SALES. Prospects in 2026 recognise Gamma and Canva AI output on sight. A deck that visibly came from a consumer AI tool actively undermines a pitch that Upcytech builds bespoke software. This is the strategic argument for owning the renderer, not just an aesthetic preference.
- VENDOR LOCK-IN VIA HOSTED DECKS. Gamma decks live at gammaUrl and Pitch/Storydoc decks live on their servers. Prospect-facing links that die when you cancel a subscription are a real commercial hazard for deals with long cycles. Always deliver a self-hosted PDF/web copy alongside any hosted link.
- TURKEY AVAILABILITY AND PAYMENT UNVERIFIED across every paid vendor listed (Gamma, Plus AI, Presentations.ai, SlideSpeak, CloudConvert). Turkish card acceptance, VAT/KDV handling and any regional restrictions were not confirmed. Verify with a small purchase before designing a lane around any of them.
- SENDING PROSPECT DATA TO THIRD PARTIES. Company-specific decks contain named prospects, pricing and sometimes confidential context. Every hosted lane (Gamma, SlideSpeak, CloudConvert, frontier LLM APIs) receives that content. Decide your policy deliberately — this is another concrete argument for the local free lane on sensitive deals.
- RESEARCH GAP FROM AN EXHAUSTED SEARCH BUDGET: this session's 200 web searches were spent before I began, so findings come from direct fetches of primary sources I could name from memory. Products that emerged in the last ~12 months and that I could not name would not appear here at all. Treat the item list as thorough on the names you asked about, but not as a complete market census.
