## Özet

As of Aug 2026 the programmable-design landscape splits into three tiers. (1) Big-platform APIs are real but gated: Canva's Connect APIs now cover designs, assets, exports, folders, comments, imports, merges, resizes, analytics and webhooks — but Brand Templates + Autofill, the only true "on-brand template fill" path, still require the acting user to be in a Canva Enterprise org. Canva does ship an official remote MCP server (mcp.canva.com/mcp, 40+ tools, CIMD auth) where export works on all plans, resize needs Pro, autofill/brand kits need Enterprise. Figma's REST API can render any node to PNG/JPG/SVG/PDF for free, but it cannot write file content, and the Variables (design-token) endpoints are Enterprise-plan + Full-seat only. The new remote Figma MCP server closes that gap: it can now write to canvas, free during beta, with 6 tool calls/month on Starter. Adobe Firefly Services (Firefly, Photoshop, Lightroom, InDesign Data Merge, Illustrator, Express, Content Tagging) is the most powerful templating engine on the market and the least solo-operator friendly: OAuth server-to-server via Developer Console, enterprise entitlement, effectively ~$1k/mo minimums. (2) Template-as-a-service (Bannerbear, Placid, Templated, HCTI, APITemplate, RenderForm, Orshot, Switchboard, Abyssale, DynaPictures) is a commoditised $9–$49/mo market with 30–50 free credits; Placid, HCTI and Orshot now ship MCP servers. (3) The cheapest, most controllable path for a Turkish-language solo operator is self-hosted: Satori+resvg or Playwright/Gotenberg rendering React/HTML templates whose CSS variables are generated by Style Dictionary from one token file — zero marginal cost, full Turkish typography control, and the same tokens feed Marp/Slidev decks and PptxGenJS exports. Penpot (MPL-2.0, self-hostable, native W3C DTCG tokens, official MCP) is the only open-source visual editor that closes the loop.

<details><summary>Notlar</summary>

**Canva Connect API** — Brand template IDs migrated to a new format in Sept 2025 (old IDs accepted 6 months). Public integrations must pass Canva review + brand guidelines. Video assets not supported for autofill. Rate limits are documented per-endpoint, not globally.

**Canva Autofill + Brand Templates API** — Docs state plainly: 'your integration must act on behalf of a user that's a member of a Canva Enterprise organization.' Only text and image field types; images must be pre-uploaded as assets (no external URLs); no video autofill.

**Canva MCP server (mcp.canva.com/mcp)** — Per-tool rate limits: mostly 100 req/min for reads, 20–50 req/min for creative/transactional ops, 30 req/min for asset upload. Separate 'Dev MCP' exists for building Canva Apps/Connect integrations (docs-assistant, not a design tool).

**Canva Dev MCP server** — Do not confuse with the Design MCP at mcp.canva.com/mcp; different server, different purpose.

**Figma REST API** — CRITICAL LIMIT: the REST API is read-only for file content. There is NO endpoint to change a text node. So 'render a frame to PNG with dynamic text' via REST alone is impossible — you need the Plugin API, the MCP write tools, or duplicate-and-edit tricks. A past bug where REST PNGs were less anti-aliased than UI exports has been fixed per the changelog.

**Figma Variables REST API (design tokens)** — Guests cannot use it at all. Read needs file View access, write needs Edit access. This is the single biggest reason not to make Figma the source of truth for your brand tokens.

**Figma MCP server (remote + desktop)** — 14 tools as of early 2026. Code Connect requires Organization/Enterprise. The 6-calls/month Starter cap makes the free tier useless for pipelines — budget for one Professional Full seat ($16/mo) if you go this route.

**Figma Plugin API** — This is the structural reason Figma is a poor headless template engine. Third parties (Orshot, Bannerbear-style services) sell 'Figma as a template API' precisely because Figma won't do it natively.

**Figma Make** — UNVERIFIED whether any Make-specific API is planned. Credit consumption per generation is not published.

**Figma Buzz** — Closest Figma answer to Canva Brand Templates + Autofill. UNVERIFIED: whether spreadsheet/CSV bulk-fill exists and whether an API is on the roadmap.

**Adobe Firefly Services** — Custom Models API is genuinely the best 'train on my brand aesthetic' offering available. If you ever scale, this is the upgrade path. Adobe restructured Photoshop API and Firefly API into independent products in early 2025.

**Adobe InDesign API (Data Merge)** — 2026 updates added multiline record support, UTF-8 CSV (emoji + international text — relevant for Turkish diacritics), hyphenationSettings and dictionarySettings exclusion lists. Docs last updated 2026-04-21.

**Adobe Photoshop API** — Became an independent product from Firefly API in early 2025. Lightroom API (auto-tone, presets, edits) sits alongside it in the same entitlement.

**Adobe Express API + Embed SDK** — The documented pattern (Express API to bulk-generate variations, Embed SDK for last-mile human edits) is exactly the architecture you want — just not at this price/approval friction.

**Penpot** — Licence: MPL-2.0 (weak copyleft — file-level; fine for personal use and for building on top, unlike AGPL). The API is an internal RPC API auto-generated from source: NOT a stability-guaranteed public REST contract, and export/render endpoints are undocumented. Webhook docs are explicitly incomplete. Treat the API as 'works but may break on upgrade'.

**Penpot MCP server** — Licence MPL-2.0. Remote mode disables local filesystem access and supports multiple Penpot users on one server. Because it runs arbitrary plugin-environment code, treat prompt-injected design content as untrusted.

**Polotno SDK** — UNVERIFIED: whether a separate hosted cloud render API (api.polotno.com) exists and what it costs — the pricing page mentions 'optional cloud render requests' with no price. Free tier is dev-server only; production needs a licence.

**Fabric.js** — Licence MIT. Node rendering needs node-canvas + jsdom (native build deps, Node >= 20); those deps are the usual source of font/emoji headaches — install Turkish-capable fonts in the container.

**Konva** — Licence MIT (stated in repo LICENSE — UNVERIFIED by direct file read in this pass). skia-canvas backend generally handles complex text shaping better than node-canvas.

**tldraw SDK** — Since SDK 4.0 the free tier is development-environments-only plus a watermarked hobby licence. Your use is personal/non-commercial today, so the hobby licence may apply — but if you ever productise, budget for the commercial licence.

**Excalidraw** — Licence MIT. Headless/server-side rendering isn't first-class — export helpers assume a browser/DOM, so you'd run them under Playwright or jsdom. Excalidraw+ (hosted) is a separate paid product.

**Rive** — Runtimes are MIT-licensed (rive-app/rive-runtime), which is unusually generous. Weak spot for your pipeline: producing a rendered MP4/GIF for Instagram/Reels from a .riv needs your own headless capture (Playwright + canvas record), not an official API.

**Lottie / dotLottie (LottieFiles runtimes)** — Lottie JSON colours can be rewritten programmatically, so your design tokens can recolour an animation at render time. To get an MP4 you still need headless capture (Playwright + dotlottie-web) or a service like Templated/Placid video endpoints.

**Satori** — Licence MPL-2.0. Hard limits that matter for you: NO RTL, no advanced typography (kerning/ligatures), no z-index, no calc(), no 3D transforms, no WOFF2 (TTF/OTF/WOFF only), no React hooks. Turkish is LTR so RTL is a non-issue, but TEST Turkish glyphs (ğ ş İ ı) and font subsetting carefully. Satori outputs SVG only — you need resvg for PNG.

**resvg** — Dual-licensed Apache-2.0 OR MIT. No native/system text rendering — you must supply font files explicitly, which is actually good for reproducibility but means you MUST bundle a Turkish-complete font (e.g. Inter, Noto Sans) or glyphs will drop.

**Playwright** — Licence Apache-2.0. Cost is latency (~0.5–2s/render) and container size (~1GB with browsers). Deterministic output requires pinning the browser version and installing fonts in the image — otherwise Turkish characters or emoji silently fall back.

**Puppeteer** — Licence Apache-2.0 (UNVERIFIED by direct read this pass). Choose one of Playwright/Puppeteer, not both — duplicated Chromium downloads.

**Gotenberg** — Licence — UNVERIFIED by primary read (widely MIT). This is the cleanest way to keep Chromium out of your main app process. e-invoicing (PDF/A, ZUGFeRD) support is a bonus if you ever need Turkish e-fatura-adjacent output.

**Cloudflare Browser Run (Browser Rendering)** — Billing rounds to the nearest hour daily. Failed requests with waitForTimeout errors aren't charged. Concurrency billed on monthly average of daily peaks. Renamed from 'Browser Rendering' to 'Browser Run'.

**react-pdf (@react-pdf/renderer)** — Licence MIT. Uses its own flexbox layout engine, not a browser — CSS support is a subset and font registration is manual (register a Turkish-complete TTF explicitly). Not the same package as wojtekmaj/react-pdf (that one displays PDFs).

**Typst** — Compiler licence Apache-2.0; each Universe package/template carries its own OSI/CC licence — check per package. Excellent Unicode/Turkish support. Not a raster/social-image tool — pair with Satori or Playwright for square/story formats.

**Style Dictionary** — Licence Apache-2.0. v4 is current. W3C DTCG token format support — UNVERIFIED from the repo README in this pass, but Penpot exports DTCG so confirm the adapter before committing. This one package is what makes 'change one hex, every channel updates' actually true.

**Bannerbear** — Unpublished video/PDF credit multipliers only visible in project logs after rendering — a real budgeting hazard. No official MCP server found (UNVERIFIED).

**Placid** — No overage fees — you simply stop generating when credits run out, which is safer than surprise bills. Free unlimited previews let an agent iterate on layout without burning credits: genuinely useful for the 'propose angles → user picks' loop.

**Templated.io** — Prices quoted are billed-annually. 15-template cap on Starter is tight if you want per-channel variants (IG square, IG story, LinkedIn, ad sizes) across multiple products.

**HTMLCSStoImage (HCTI)** — 1-month image deduplication window on free tier means identical HTML returns a cached image (can be a feature or a gotcha). Because your templates are just HTML/CSS, you can move to self-hosted Playwright with near-zero rewrite — that portability is the real reason to pick HCTI over layer-based competitors.

**APITemplate.io** — Generation takes 1.2–15s. BYO S3 storage only on Enterprise tier. Custom CSS and team features start at Standard.

**RenderForm** — Free tier watermarks output, so it's evaluation-only. $9 one-time for 250 renders is the cheapest real entry price in the whole hosted-template category.

**DynaPictures** — Verify pricing directly before committing; directory listings for this product are inconsistent.

**Abyssale** — If you ever run performance ads seriously, this is the one to revisit: ad-network size compliance out of the box is a real time saver.

**Switchboard Canvas** — The built-in translation across 70+ languages is the differentiator if you ever want TR-primary content mirrored to EN for LinkedIn.

**Orshot** — Video at 1 credit per SECOND makes Reels expensive here (30s Reel = 30 credits). The 'social publishing' add-on overlaps with what you'd build yourself. UNVERIFIED whether an MCP server exists.

**Marp / Marp CLI** — Licence MIT. PDF/PPTX/image output requires Chrome, Edge or Firefox installed (same Chromium dependency as your image renderer, so reuse the container). PPTX output is image-based slides, not editable shapes.

**Slidev** — Licence MIT. Needs `npx playwright install chromium`. Because it's Vue + UnoCSS, your design tokens can drive the theme directly. Heavier than Marp; pick Marp for simple branded decks, Slidev for demos with live code and animation.

**reveal.js** — Licence MIT. Because slides are DOM, you can screenshot any slide with Playwright — handy for turning a deck into a LinkedIn carousel.

**PptxGenJS** — Licence MIT. HARD LIMIT: it creates new decks only — it cannot read or modify an existing .pptx template. If you need 'fill this existing corporate template', use Adobe InDesign API or a Google Slides duplicate-and-replace flow instead.

**Google Slides API** — The workflow: keep a master branded deck, Drive-copy it, batchUpdate replaceAllText/replaceAllShapesWithImage, then export as PDF/PPTX via Drive. This is the single best free substitute for Canva Autofill. Apps Script can run the whole thing server-free.

**Presenton** — Licence Apache-2.0 (permissive — safe for any future commercial use). Works with Ollama, LM Studio, OpenAI, Gemini, Vertex, Azure, Bedrock, Fireworks, Together, Anthropic or any OpenAI-compatible endpoint. Feed it your own .pptx as the design source to keep brand consistency.

**Gamma Generate API** — Rate limits not published (UNVERIFIED). The 125-credits-per-ultra-image tier can drain a month's allowance in one deck — pin image quality settings in your pipeline. Template-based generations cost slightly more per card.

**Tome** — Reported via secondary sources only (UNVERIFIED against a Tome-owned primary page, which no longer exists). It never had a public API. Listed here so you don't waste time evaluating it.

**Beautiful.ai / Pitch** — Beautiful.ai added a context-aware AI workflow that outlines before designing; Pitch's strength is live co-editing. Both are human-in-the-loop tools. If you want AI decks with an API, it's Gamma (paid) or Presenton (self-hosted).

### Öneriler

- Make Style Dictionary the single source of truth for your brand system: one tokens.json (colors, type scale, spacing, radii, logo paths, Turkish-safe font stack) that compiles to CSS custom properties, a Tailwind config, a Marp/Slidev theme CSS, and a JS object for PptxGenJS Slide Masters — so a single hex change propagates to every channel with no manual redraw.
- Build your primary image renderer as self-hosted HTML templates rendered by Satori + resvg for speed (sub-100ms, no browser) and fall back to Playwright when a template needs real webfonts, ligatures, CSS grid or filters that Satori's subset does not support; keep both behind one internal render(templateId, data, size) function so the engine is swappable.
- Bundle a Turkish-complete font (Inter, Noto Sans or your brand face with full Latin Extended-A coverage) into your render container and add a golden-file test that renders the string 'ĞÜŞİÖÇ ğüşıöç' at every template size — silent glyph fallback is the single most likely way your Turkish-language pipeline ships broken assets.
- Use the Google Slides API as your free Canva-Autofill substitute for decks: keep one master branded presentation, Drive-copy it per job, then batchUpdate with replaceAllText and replaceAllShapesWithImage, and export to PDF/PPTX — this gives you real brand-template autofill at zero cost while Canva keeps that feature behind Enterprise.
- Do not pay for Figma Enterprise to get the Variables API; keep tokens in your repo and, if you want Figma in the loop at all, buy exactly one Professional Full seat ($16/mo) and use the remote Figma MCP server's write-to-canvas beta plus the free GET /v1/images endpoint to render frames — and have a migration plan for when Figma makes write-to-canvas a paid usage-based feature.
- Wire the official Canva MCP server (mcp.canva.com/mcp) into your command center now for the tools that work on a Pro plan — design search, generation, export, asset upload, thumbnails — and treat Autofill/Brand Templates as permanently out of reach unless you buy Enterprise; do not architect any pipeline stage that depends on them.
- Pick HTMLCSStoImage's free tier (50 images/month, official MCP server) or Cloudflare Browser Run's free tier (10 browser-minutes/day) as your managed escape hatch, because both consume the same HTML/CSS templates as your self-hosted renderer — this keeps switching cost near zero and prevents lock-in to any layer-based template SaaS.
- Self-host Penpot (MPL-2.0, Docker) with its native W3C DTCG design tokens and the official Penpot MCP server as the one visual editing surface your agent can both read and write, but treat its RPC API as unstable — pin the Penpot version, snapshot the API responses you depend on, and never make it the only copy of your brand assets.
- For decks, run a two-track setup: Marp CLI for fast, fully token-themed standard decks (Markdown in, branded PDF/PPTX/PNG out) and self-hosted Presenton (Apache-2.0, pointed at a local Ollama or your existing model key) when you want AI to draft the deck structure — this covers the Gamma use case at zero marginal cost and keeps your content on your machine.
- Add Rive on its genuinely usable free tier ($0, 3 files, 1 project) for interactive/animated brand elements and use Lottie/dotLottie runtimes for motion whose colours you recolour from your tokens at render time — then capture MP4/GIF for Reels with Playwright rather than paying per-second video credits to a template SaaS.
- Budget deliberately: the whole recommended stack (Satori/resvg, Playwright, Style Dictionary, Marp, PptxGenJS, Google Slides API, Presenton, Penpot, Konva/Fabric) is $0/month, so reserve paid spend for exactly two things — one Canva Pro seat for the MCP export/design tools and, only if AI-drafted decks prove valuable, Gamma Pro at $25/mo for its API key.
- Design every template as data-in/asset-out with a stable JSON contract (template id, slot names, token overrides, output size) and store rendered outputs with a content hash, so the same agent call can target Satori locally, HCTI in the cloud, or Google Slides for decks without the orchestration layer knowing or caring which engine ran.


### Riskler

- Canva's most valuable capability for you — Brand Templates + Autofill — is Enterprise-gated for both the developer AND every acting user, and Enterprise pricing is sales-gated with no public number; any architecture that assumes Canva autofill will become affordable is a bet, not a plan.
- Figma is structurally hostile to headless templating: the REST API cannot write file content, the Plugin API cannot run server-side, and the Variables API is Enterprise + Full seat only. The remote MCP's write-to-canvas is the only bridge and Figma has stated it will become a usage-based paid feature after beta — a dependency that can reprice without warning.
- Satori's documented limitations (no RTL, no kerning/ligatures, no calc(), no z-index, no WOFF2) can produce subtly wrong Turkish typography that passes automated checks but looks amateurish to a native reader; you will not notice this from an English-language test suite.
- Font availability inside headless containers is a silent failure mode: resvg has no system text rendering at all and node-canvas/Playwright fall back without erroring, so Turkish diacritics or emoji can vanish from production assets with no exception raised.
- Template-as-a-service credit systems hide real costs: Bannerbear does not publish its video/PDF credit multipliers (visible only in logs after you render), Gamma charges up to 125 credits for a single ultra-quality image, and Orshot bills video at 1 credit per second — a 30-second Reel is 30 credits.
- tldraw's 4.0 licence change (production requires a paid key; free hobby licence is watermarked) is a live example of an OSS-adjacent SDK relicensing under you; Polotno at $249–$899/mo shows the same category risk. Prefer MIT/Apache/MPL libraries you can fork over SDKs with licence-key enforcement.
- Penpot's API is an auto-generated internal RPC surface with no stability guarantee and explicitly incomplete webhook documentation — a Penpot upgrade can break your pipeline silently, and there is no documented render-to-PNG endpoint to rely on.
- Adobe Firefly Services is the only stack that does true PSD/InDesign brand templating headlessly, but it has no published self-serve price, requires Adobe Developer Console OAuth server-to-server credentials and an enterprise entitlement, and secondary sources put the floor near $1,000/month — treat it as unreachable and design around it rather than prototyping against it.
- Automated posting terms are a separate risk layer from rendering: none of these design tools grant publishing rights, and the platform APIs you hand assets to (Instagram, LinkedIn, X) carry their own automation restrictions — verify those before wiring 'schedule the post' to anything that renders.
- Any MCP server that executes model-authored code inside a design environment (Penpot MCP explicitly runs arbitrary plugin-environment snippets; Figma MCP writes to canvas) turns prompt-injected content in a design file into an execution path — sandbox them and never point them at files containing untrusted third-party content.
- Several vendors in the template-SaaS tier are small businesses with a single pricing page and no SLA; DynaPictures alone showed three mutually contradictory pricing descriptions across directories in this research pass. Assume any of Templated, RenderForm, Switchboard, Orshot or DynaPictures could reprice or disappear, and keep templates in a portable format (HTML/CSS) rather than their proprietary layer editors.
