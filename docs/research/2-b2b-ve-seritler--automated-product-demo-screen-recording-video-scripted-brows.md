## Özet

The 2026 landscape splits cleanly into four layers, and the good news for a solo operator is that the expensive layer is optional. LAYER 1 (capture): scripted capture is a solved, free problem — Playwright's built-in `recordVideo` produces WebM but caps at viewport-scaled-to-800x800 by default and its frame rate is undocumented (CDP screencast is frame-event-driven, not fixed-fps), so for 1080p60 you drive a HEADED Chromium under Xvfb and capture the X display with ffmpeg x11grab, or use `neko` (Apache-2.0) which already packages browser+virtual display+capture in Docker. LAYER 2 (polish): this is where Screen Studio built a business, and in 2026 there are credible OSS clones (Beam MIT, OpenScreenStudio AGPL-3.0, CloseScreen, Cap AGPLv3-with-MIT-crates) — but ALL are GUI desktop apps, macOS/Windows only, with NO headless CLI. That is the single biggest gap: nothing OSS gives you programmatic auto-zoom/cursor-smoothing. The practical answer is to synthesize the effects yourself in a compositor. LAYER 3 (composition): Remotion is the best DX and — critically — is FREE for individuals and companies up to 3 employees (you qualify as a solo operator); beyond that it's $100/mo minimum or $0.01/render. Revideo (MIT) and Motion Canvas (MIT) are the licence-clean fallbacks; Editly (MIT, ffmpeg) is the zero-risk lane. Hosted JSON APIs (Shotstack $0.20-0.30/min, JSON2Video from $16.95/mo, Creatomate) are the no-infra premium lane. LAYER 4 (interactive): for B2B pre-meeting assets, Arcade/Storylane/Supademo all have real free tiers but gate APIs behind Enterprise; there is NO true OSS Arcade clone — rrweb (MIT) is the building block everyone forks. Turkish is well supported for TTS/captions (Gemini TTS free tier, ElevenLabs $6/mo, whisper.cpp free).

<details><summary>Notlar</summary>

**Playwright video recording (recordVideo)** — CONFIRMED from docs: video size defaults to viewport scaled to fit 800x800; video only written after context.close(). Frame rate is NOT documented anywhere in official docs — it is driven by CDP Page.startScreencast frame events, so it is variable and typically well under 60fps. Output is WebM/VP8, which you must transcode. Verdict: fine for 'here is the flow', not for a premium sales asset. Set viewport 1920x1080 AND recordVideo.size 1920x1080 explicitly or you get an 800px letterbox.

**Headed Chromium + Xvfb + ffmpeg x11grab** — This bypasses every Playwright video limitation. Use `-draw_mouse 1` to capture the real cursor, or `-draw_mouse 0` and composite your own smoothed cursor later (recommended — see cursor-smoothing note). Encode with `-c:v libx264 -preset veryfast -crf 18 -pix_fmt yuv420p` for edit-friendly footage, or ffv1/prores for lossless intermediate. Playwright Docker docs do NOT mention xvfb-run (UNVERIFIED whether bundled) — install it yourself. Add `--ipc=host` to docker run (documented Chromium OOM fix) and `--force-device-scale-factor=2` for retina-crisp text you can downscale.

**neko (m1k1o/neko)** — CONFIRMED Apache-2.0 (permissive — no AGPL contamination, unlike Cap). Docs explicitly list 'session recording: broadcast via RTMP and save to files' and 'automated browser tasks with Playwright/Puppeteer while monitoring'. Ideal for the Creative Suite: one container = one deterministic demo environment, reusable across prospects.

**puppeteer-screen-recorder** — UNVERIFIED: could not fetch the repo to confirm licence, maintenance, or achievable fps. Listed for completeness. The underlying CDP screencast approach is inherently variable-framerate and drops frames under load — do not expect smooth 60fps. If you already use Puppeteer, prefer switching to Playwright or to x11grab rather than adopting this.

**Chrome DevTools Recorder** — CONFIRMED from docs: records clicks/form fills, supports replay, slow-motion, breakpoints, step editing, and customization via extensions. CONFIRMED: the docs do NOT indicate any video recording capability — it captures the flow, not pixels. Export-to-Puppeteer is the documented extension path. This is the ideal way for a non-coder-mode capture of 'what to show this prospect' that then becomes a versioned script in the git repo.

**Browserless** — CONFIRMED licence string: 'SSPL-1.0 OR Browserless Commercial License'. SSPL is NOT OSI-approved and is viral for service providers — for a company selling SaaS this is a real (if remote) legal question. CONFIRMED Session Replay video is cloud/enterprise only, not in the OSS build. Use plain Playwright + Xvfb instead; there is no capability here you need.

**Cap (CapSoftware/Cap)** — CONFIRMED licence: AGPLv3 for everything except `cap-camera*` and `scap-*` crates which are MIT. LICENCE WARNING: AGPLv3 means if you host a modified Cap and expose it over a network, you owe source. Using the unmodified self-hosted instance internally to record your own demos is fine. The MIT-licensed `scap` capture crate is separately reusable — that is the genuinely valuable carve-out if you ever build your own recorder. CONFIRMED: no Linux desktop build (macOS/Windows only); server runs on Linux. UNVERIFIED: exactly what the apps/cli binary can do headlessly — investigate before betting on it.

**Screen Studio** — CONFIRMED from the site: subscription $20/mo or $9/mo annual; a past one-time licence is grandfathered. CONFIRMED macOS only — the Windows FAQ entry exists but is unanswered, i.e. still not shipped. CONFIRMED: no mention anywhere of CLI, API, or automation. Fundamentally incompatible with an agentic, git-backed, Linux pipeline. Its VALUE to you is as a design reference: copy its effect vocabulary (ease-in-out zoom to click point, cursor lag/smoothing, rounded window with shadow on gradient) into Remotion components.

**Beam (ExtraBinoss/Beam)** — CONFIRMED MIT licence and Windows/macOS only (Linux 'not yet'). CONFIRMED features include smart zoom, cursor replacement, backgrounds/gradients/frames. CONFIRMED: no CLI or headless export. 11 stars / 475 commits = one-person project, real bus-factor risk. Its MIT source is the most legally comfortable place to READ how auto-zoom and cursor smoothing are implemented, then port that maths into your Remotion components. This is precisely the effect that separates a premium demo from an amateur one, so it matters. Do the zoom in Remotion/Revideo where you have float precision, or supersample at 2-4x and downscale. Do not build your auto-zoom on raw zoompan.
- AVAILABILITY / TURKEY — none of the vendors state Türkiye restrictions, but several practical frictions apply for a Turkish company: USD card payments and FX exposure on every subscription, possible 3-D Secure failures, and Turkish KDV/withholding treatment on foreign SaaS invoices. Concentrate spend on few vendors with annual billing, and prefer the free/self-hosted lane precisely because it removes this whole class of operational risk. Gemini API, Cloudflare and Bunny are all available in Türkiye.
- TURKISH LANGUAGE QUALITY IS THE BIGGEST UNTESTED ASSUMPTION IN THIS REPORT. Confirmed Turkish support: Gemini TTS (tr listed), Azure tr-TR (STT + tr-TR-TurkuNeural, but NO styles, NO voice conversion, NO Neural HD voices for Turkish), Submagic (Turkish explicitly named). Budget a real evaluation day: render the same 200-word Turkish script through every candidate and listen.
- CATEGORY RISK — the OSS 'Screen Studio clone' space is a churn field of very young projects: Beam has 11 stars, OpenScreenStudio has 2, CloseScreen is a fork-of-a-fork whose canonical repo path I could not even resolve (404). All are GUI-only, none has a CLI, and most are macOS/Windows only while you are on Linux. Treat every one of them as a source of IDEAS to port, never as a dependency. Building the effects yourself in Remotion is both lower-risk and higher-quality, because you have click intent that they must infer.
- VENDOR/BUSINESS RISK — the interactive-demo category uniformly gates APIs behind Enterprise (Arcade, Storylane, Navattic all confirmed), and free tiers cap you at ONE published demo (except Supademo's five). Any plan that assumes 'we will automate per-prospect interactive demos via API' is not fundable at solo-operator prices. Either accept manual interactive demos on a free tier, or build on rrweb. Do not architect around an API you cannot buy.
- COST-MODEL RISK for your mandatory pre-run estimate: the vendors use incompatible units, and mixing them up will make your estimator lie. Shotstack and JSON2Video bill per SECOND/MINUTE of output (exact and easy). Creatomate bills CREDITS that scale with resolution AND framerate (its '14 credits/minute' figure is for 720p25 — a 1080p60 demo costs several times that). Cloudflare Stream bills per MINUTE regardless of file size. Bunny bills per GB, so bitrate directly drives cost. Mux bills encoding, storage and delivery as three separate per-minute lines. Build the estimator with explicit per-vendor unit conversion and calibrate each against one real test render before showing a number to yourself as truth.
