# Completeness critique: gaps, contradictions and stale claims across the 13-agent research for a solo-operator agentic brand/creative suite (Turkey, Turkish-language, Aug 2026)

> Kaynak: araştırma journal'ı, damıtılmış. Ham kayıt
> `~/.claude/projects/.../subagents/workflows/` altında.

## Özet

The 13 agents produced excellent depth on generation (image/video/audio), orchestration and publishing transport, but left whole capability layers with NO tool assigned, and two of the user's six named use cases are materially under-served.

The single largest omission is LinkedIn document/carousel posts — the highest-performing LinkedIn format. LinkedIn's Documents API is real, is reachable with `w_member_social` on a personal profile, accepts PDF/PPTX up to 100MB and 300 pages, and no agent mentioned it. Second: nothing was assigned to "product demo video" other than AI video models, when the correct primitive is a scripted Playwright session with video recording plus Cap, both free. Third: Instagram's Content Publishing API has no trending-audio parameter at all — the pipeline as specced cannot ship a competitive Reel.

Entire categories were skipped: paid-ads creative and the ad platform APIs (and Meta's own docs say standard access to `ads_management` is sufficient for your OWN ad account with no App Review — directly contradicting the MCP agent's "HOLD, go through an aggregator" verdict); competitor ad intelligence via the free Meta Ad Library API covering all ad categories in 200+ countries; email/newsletter; landing pages; creative A/B testing; localisation; asset versioning; stock B-roll; background removal; podcasting; print/merch; CRM/booking.

Most consequentially for a Turkish operator: not one agent surfaced a Turkish-native model. Kumru-2B (Apache-2.0) ships a Turkish BPE tokenizer where rivals spend 38–98% more tokens, ytu-ce-cosmos publishes a Turkish ModernBERT family including a guardrail classifier, and Trendyol publishes a Turkish TTS. The "verify Turkish quality yourself" advice was right; the tools to do it were never found.

<details><summary>Notlar</summary>

**LinkedIn Documents API (rest/documents + rest/posts)** — Docs explicitly list w_member_social ('Post, comment, and like posts on behalf of authenticated member') as an accepted permission, and state that for person-URN owners 'the caller must match the document owner' — i.e. a solo operator posting their own carousel needs no partner review. Hard limits: 100MB, 300 pages, PPT/PPTX/DOC/DOCX/PDF only. SYNCHRONOUS_UPLOAD is NOT supported. Marketing version 202507 is already sunset; pin Linkedin-Version and expect monthly churn. Pairs perfectly with the deck stack the agents already found (Marp/Slidev/PptxGenJS → PDF → document post).

**LinkedIn Images API (rest/images)** — Critical gotcha nobody flagged: on versioned gateway calls w_member_social is WRITE-ONLY — a token holding only w_member_social cannot GET /rest/images and will receive HTTP 403 'Accessing this image resource is forbidden'. Your asset-library reconciliation job must therefore track image URNs locally rather than reading them back. Limits: <36,152,320 pixels; JPG/GIF/PNG only; GIF up to 250 frames. altText max 4,086 chars (recommend <120). downloadUrl is signed and expires — same download-immediately discipline the image agent flagged for Ideogram.

**Instagram Reels audio / trending sound selection** — Absence of evidence in the primary doc, not a positive denial — but the doc is exhaustive about supported params and explicitly states 'Filters are not supported' and 'Shopping tags are not supported'. Practical consequence: an API-published Reel gets your own audio bed (ElevenLabs/ACE-Step) but no trending-sound reach boost. Either (a) publish Reels manually when a trending sound matters, or (b) treat Reels as an owned-audio format and lean on hook/caption/motion instead. This materially changes the Reels pipeline design and no agent caught it.

**Instagram is_ai_generated publishing parameter** — The compliance agent correctly identified that Article 50 became applicable 2026-08-02 and that Meta auto-labels, but never connected it to the concrete API field that exists to declare it. Combine with the C2PA/ExifTool stamping the brand-as-code agent recommended: C2PA survives your archive, is_ai_generated survives the upload transcode.

**Instagram trial_params (Trial Reels)** — Maps directly onto the user's 'agent proposes angles → user picks' loop: publish 3 trial Reels, let Instagram's own non-follower distribution score them, graduate the winner. Exact schema of trial_params and graduation rules were not read in this pass — verify before building.

**Instagram alt_text parameter** — Explicitly IMAGES ONLY: the doc states 'Reels and stories are not supported' for alt_text. So your accessibility layer is asymmetric across formats, which matters if you care about reach among screen-reader users or about the SEO/alt-text discipline the agents recommended generally.

**Playwright video recording (scripted product demo capture)** — The 13 agents assigned Veo/Seedance/Kling to 'product demo video', which is exactly wrong: those models hallucinate your UI. The correct pipeline is seed demo data → Playwright script drives the real app → record video → ffmpeg zoom/pan + Remotion brand frame + ElevenLabs Turkish VO. Default video scales to fit 800x800, so you MUST set the viewport explicitly to get 1920x1080 or 1080x1920. Playwright also supports action annotations (element outlines, titles) which double as free callout overlays for an explainer. Playwright MCP was already in the stack — nobody connected it to this job.

**Cap (CapSoftware/Cap)** — Licence CONFIRMED as mixed: cap-camera* and scap-* crates are MIT, everything else is AGPLv3. 20.8k stars, 8,118 commits, actively developed. AGPLv3 on the main body means the same 'talk to it over HTTP, never vendor it' discipline that applies to Postiz. No Linux desktop app listed — a real constraint if the user is on Linux (the working environment here is Linux), which pushes you back to Playwright + ffmpeg or OBS.

**Supademo / Storylane / Arcade (interactive product demos)** — Flagged because the category is a genuine content format for a bespoke-software business and was entirely absent from all 13 reports, but the automation story does not check out. The OSS substitute is Playwright-driven screenshot sequences rendered into a self-hosted clickable walkthrough, or simply a recorded Playwright demo video.

**Meta Ad Library API (ads_archive endpoint)** — Primary doc confirms categories include FINANCIAL_PRODUCTS_AND_SERVICES_ADS, EMPLOYMENT_ADS, HOUSING_ADS, POLITICAL_AND_ISSUE_ADS and all categories — the widespread belief that it is political-ads-only is wrong. Important geographic asymmetry for a Turkish operator: 'Ads that did not reach any location in the EU will only return if they are about social issues, elections or politics' — so Turkey-targeted commercial ads may NOT be retrievable, while EU-targeted ones are. Verify TR coverage empirically before building a Turkish competitor-ad dashboard. This is exactly the 'competitor monitoring' gap, solved for free, with the one caveat that it may not cover your actual market.

**Meta Marketing API — standard access for your own ad account** — The MCP agent wrote 'Meta / Instagram — NO official MCP server … HOLD — build against a publishing aggregator rather than integrating Meta directly; direct integration means App Review, Business verification'. That is wrong for the single-tenant case, and the publishing agent got it right for organic. The same Standard-Access logic that unlocks Instagram publishing also unlocks ads. Two current tiers only: Limited Access (auto-granted when you add the Marketing API product) and Full Access (App Review). 'Development' and 'Standard' are legacy tier names. Development-mode spend limit is not stated in the doc — verify before running a live budget.

**Google Ads API (Basic Access)** — Doubles as an alternative to the analytics agent's DataForSEO recommendation ($50 deposit) for TR search-volume data — Google Ads API Keyword Planner data is free with an active account. 15,000 ops/day is far beyond a solo operator's needs. No agent covered ad platform APIs at all despite 'ads' being an explicitly named pipeline in the brief.

**TikTok Commercial Content API (ad/commercial content library)** — Primary page states 'in this phase we are ONLY including data from EU countries, while a researcher/professional requesting it can be located in any country' — so a Turkey-based applicant CAN apply, but gets EU data. Retention: for the ad's run period plus one year after last shown. Useful only if you sell into the EU. Distinct from the TikTok Research API the analytics agent correctly marked AVOID; this one is at least application-open.

**Kumru-2B (vngrs-ai)** — Apache-2.0, commercial use permitted. The tokenizer claim is the operationally decisive one: competing models 'spend between 38% to 98% more tokens than Kumru while still having larger vocabulary sizes' — which means every Turkish prompt you send to Claude/Gemini is being billed at up to 2x the token count a Turkish-native tokenizer would use. Reported to surpass LLaMA-3.3-70B, Gemma-3-27B, Qwen-2-72B and Aya-32B on the Cetvel benchmark, especially at Turkish grammatical error correction — which makes it a natural Turkish copy LINTER sitting after your frontier-model draft, not a replacement for it. Released 2025 by VNGRS (Turkish NLP company).

**Cetvel (KUIS-AI) — Turkish LLM benchmark/leaderboard** — Referenced as the benchmark on the Kumru-2B model card; the Space itself did not render substantive content to automated fetch, so task list, maintainer details and current rankings are UNVERIFIED. Still worth naming because the entire research corpus concluded 'Turkish quality is unverified across the board' without pointing at a single Turkish eval. Build your own 20-prompt Turkish brand-voice eval set and score candidates against it; use Cetvel as the external sanity check on model selection.

**ytu-ce-cosmos ModernBERT-TR family** — This directly fills two gaps: (1) the brand-as-code agent recommended LanceDB/sqlite-vec for the brand KB but never named a TURKISH embedding model — a multilingual English-centric embedder retrieves badly over Turkish agglutinative text; modernbert-tr-embed is the right encoder. (2) The knowledge-modelling agent recommended a deterministic 'brand_check' linter before publishing but had no classifier — modernbert-tr-guardrail is a candidate. Also includes CosmosGemma and CosmosLLaMa Turkish LLM variants referenced in their Spaces. Per-model licences must be checked individually before commercial use.

**Trendyol-TTS** — Corrects a specific claim: the audio agent wrote 'Microsoft VibeVoice — AVOID for Turkish' and did not evaluate the VoxCPM line at all, concluding Turkish self-hosted TTS was limited to Chatterbox/Piper/XTTS. This exists. Card says MIT, but explicitly warns you must separately verify the upstream VoxCPM2 licence AND that the training dataset is private — so the effective commercial licence is NOT clean. Card also states it is 'a research and prototyping artifact, not a managed production endpoint' and recommends human review and content moderation before commercial deployment. No voice cloning. Bake it off against Chatterbox Multilingual V3 on your own Turkish script before committing.

**Trendyol-LLM-Asure-12B** — Licence is the Gemma Terms of Use, NOT Apache/MIT — it carries use restrictions and a prohibited-use policy that survive fine-tuning and redistribution. That is materially different from Kumru-2B's Apache-2.0 and should gate which one you build on. No Turkish benchmark numbers published on the card. Trendyol also publishes Trendyol-LLM-8B-T1 (Turkish & English reasoning) and Trendyol-Vision-Flash/Master; licences not shown at org level.

**Zemberek-NLP** — Repo states 'This project is now in slow maintenance mode'; last release 0.17.1 dated 2019-07-23. Apache-2.0 licence is clean. 1.3k stars. For a 2026 pipeline, prefer Kumru-2B for grammatical error correction (it is benchmarked on exactly that task) and keep Zemberek only for deterministic morphology/deasciification where a frozen rule-based tool is an advantage rather than a liability. Named here because the Turkish-typography and Turkish-copy risks were raised repeatedly across the reports with no tool ever proposed.

**Pexels API** — Commercial use permitted: 'you are welcome to use Pexels content for anything you'd like'. BUT attribution is MANDATORY — a prominent link to Pexels in your application plus photographer credit where possible — which means your asset-metadata schema needs an attribution field and your render templates need somewhere to put it. Explicitly forbidden: copying or replicating core Pexels functionality, and working around the rate limit. Cheaper and more reliable than generating 30 seconds of AI B-roll at $0.05-0.40/sec, and it sidesteps the Turkish-diacritic and brand-consistency problems entirely for background footage.

**Unsplash API** — Two obligations that bite an automated pipeline: (1) you MUST fire a GET to the download endpoint whenever a photo is used, for photographer stats; (2) Unsplash REQUIRES you to hotlink the returned image URLs rather than storing copies locally — the exact opposite of the 'download and persist bytes immediately' rule the image agent correctly established for generation providers. That makes Unsplash awkward inside a DAM-centric suite. Pexels is the better default; keep Unsplash as a second source.

**rembg** — 24.3k stars, 541 commits. Turkey-specific: any Turkish marketing email requires İYS-registered consent to be legally valid, so Listmonk's subscriber table must carry an İYS consent reference field — see the İYS item. ### Öneriler

- Build LinkedIn document (carousel) posting as a first-class pipeline immediately, because it is the highest-engagement LinkedIn format, it is reachable today with w_member_social on your personal profile, and it composes perfectly with the deck stack the research already selected: render Marp or Slidev to PDF from your Style Dictionary tokens, POST /rest/documents?action=initializeUpload with owner=urn:li:person:{id}, PUT the file, then POST /rest/posts with content.media={title,id} — respecting the 100MB and 300-page ceiling and pinning the Linkedin-Version header.
- Reassign 'product demo video' away from AI video models entirely and build it as a scripted Playwright session with video recording against your own running SaaS with seeded demo data, because Veo, Seedance and Kling will hallucinate your UI while Playwright renders it exactly — and remember to set the viewport explicitly, since Playwright's default video scales to fit 800x800 rather than 1080x1920.
- Redesign the Reels pipeline on the assumption that trending audio is unavailable: Meta's Content Publishing documentation exposes no audio_name, audio_id or trending-sound parameter, so either accept owned-audio Reels built from ElevenLabs Turkish voiceover plus an ACE-Step or ElevenLabs Music bed, or keep a deliberate manual publish path for the occasions when a trending sound is worth the human step.
- Wire the free Meta Ad Library API (ads_archive) into your competitor-intelligence loop this week, since it covers all ad categories across 200+ countries rather than only political ads as is widely believed — but verify Turkish coverage empirically first, because the docs state that ads which did not reach any EU location return only if they concern social issues, elections or politics, which may exclude your actual market.
- Treat paid ads as reachable rather than blocked and ignore the MCP agent's advice to route Meta through an aggregator: Meta's own authorization documentation states that standard access to ads_read and ads_management is sufficient when your app manages only your own ad account, and Google Ads Basic Access (15,000 operations per day, roughly five business days of review) is realistically obtainable for a solo operator — which also gives you free Keyword Planner search-volume data for Turkish and may remove the need for the $50 DataForSEO deposit.
- Add Kumru-2B (Apache-2.0) as a Turkish quality gate sitting after your frontier-model draft rather than as a replacement for it, because it is trained from scratch on Turkish with a purpose-built 50,176-token Turkish BPE tokenizer, is reported to beat LLaMA-3.3-70B and Gemma-3-27B on the Cetvel benchmark at Turkish grammatical error correction, and its tokenizer finding — that competing models spend 38 to 98 percent more tokens on Turkish — means you are currently paying up to double for every Turkish prompt you send to a frontier model.
- Use ytu-ce-cosmos/modernbert-tr-embed as the embedding model for any retrieval over your Turkish brand knowledge base instead of a multilingual English-centric embedder, and evaluate modernbert-tr-guardrail as the deterministic classifier inside the brand_check pre-publish gate that the knowledge-modelling research specified but never gave a model to run — checking each model's individual licence first, since the organisation page displays none.
- Add stock footage and photography as a deliberate pipeline tier before reaching for AI video, using the Pexels API (free, 200 requests per hour, 20,000 per month, commercial use permitted, with photo AND video endpoints) as the default and treating Unsplash as secondary because its mandatory hotlinking requirement directly contradicts the download-and-persist-immediately discipline your asset library depends on — and add an attribution field to your asset schema, since Pexels attribution is not optional.
- Close the owned-audience gap by adding either Ghost (MIT, so cleanly forkable, covering landing pages, blog, memberships and native newsletters in one Admin API) or Listmonk (AGPL-3.0, single Go binary plus Postgres, complete REST API) — but do not send a single Turkish marketing email until you have confirmed the İYS consent-registration obligation and integration path with a Turkish adviser, and design the subscriber schema with İYS consent reference, source, timestamp and channel fields from day one rather than retrofitting them.
- Adopt DVC (Apache-2.0) to version generated creative assets alongside the git-based brand system, because the brand-as-code architecture pins tokens.json and skill files in git but has no home for the 200MB video renders and 4MP hero images — DVC keeps pointers in git and bytes in S3/R2, which is what makes 'which palette and logo lockup produced this post' answerable by checkout rather than by guesswork.

### Riskler

- The research corpus contains a direct, unresolved contradiction about Meta integration — the MCP agent says direct integration requires App Review and Business verification and recommends paying an aggregator, while the publishing agent and Meta's own authorization docs say standard access suffices for a single-tenant app managing your own accounts. Acting on the wrong one adds an unnecessary $149-599/month Ayrshare dependency or, in the other direction, leaves you unprepared if Meta reinterprets single-tenant policy.
- Not one of the thirteen agents surfaced a single Turkish-native model, benchmark or NLP tool, while simultaneously flagging 'Turkish quality is unverified' as a top risk in nearly every report. The corpus therefore systematically under-searched the user's own language, and the same blind spot likely extends to Turkish-language marketing conventions, Turkish social platforms and Turkish creator norms that were never examined at all.
- Instagram's inability to attach trending audio via the API is a silent capability gap rather than an error: the pipeline will publish Reels successfully and they will simply underperform, which is the hardest class of failure to diagnose because nothing breaks.
- Licence exposure is now heavily concentrated in AGPL across the added categories: Listmonk, Castopod, Formbricks, Cap's main body and Postiz are all AGPL-3.0, Weblate is GPL-3.0, and combined with the AGPL projects already selected this means almost the entire non-generation half of the suite carries source-disclosure obligations the moment a modified instance is exposed over a network to anyone else. Ghost (MIT), DVC (Apache-2.0), Kumru-2B (Apache-2.0), ntfy (Apache-2.0/GPLv2) and Tolgee's core (Apache-2.0) are the permissive escape routes and should be preferred where functionally equivalent.
- Model licences inside the newly-found Turkish stack are not uniform and not clean: Trendyol-LLM-Asure-12B is under the Gemma Terms of Use with prohibited-use restrictions that survive fine-tuning, Trendyol-TTS is nominally MIT but its card explicitly tells you to separately verify the upstream VoxCPM2 licence and warns the private training dataset is unverified, and the ytu-ce-cosmos organisation page displays no licences at all. Only Kumru-2B (Apache-2.0) is confirmed clean.
- Trendyol-TTS's own model card states it is 'a research and prototyping artifact, not a managed production endpoint' and recommends adding safeguards, human review and content moderation before commercial deployment — so treating it as a drop-in free Turkish voice for published brand content is a misuse of what the authors are offering.
- rembg's MIT wrapper licence conceals a heterogeneous model layer: BRIA rmbg 2.0, BiRefNet variants, SAM and the u2net family all originate from different projects with different commercial terms, so 'rembg is MIT' is true of the code and false of the thing you actually ship.
- The Meta Ad Library API's EU asymmetry may make it useless for the user's actual market: non-political ads that never reached an EU location are excluded, which plausibly means Turkey-targeted competitor commercial ads are not retrievable. The tool is free and high-value, but it may be free and high-value for a market the user does not sell into.
- The TikTok Commercial Content API is EU-data-only in its current phase, so a Turkish operator can apply and be approved and still receive nothing relevant — a failure mode that only surfaces after the application and integration work is done.
- Unsplash's hotlinking requirement is architecturally incompatible with the self-hosted, download-immediately asset library that every agent recommended, and complying with one obligation means violating the other. Pexels does not have this conflict, which is a stronger reason to prefer it than image quality.
- Adding email, ads, CRM, booking, localisation, podcasting and merch to a stack that already contains ten-plus self-hosted services compounds the operations burden the OSS agent already flagged as the most likely real failure of the project. Every gap identified here is a genuine gap; not every gap needs filling in year one, and filling all of them guarantees the operator spends their time on upgrades and credential rotation rather than on Turkish content.
- Several verdicts in this critique rest on absence of evidence from a single primary page rather than positive confirmation — most consequentially the Instagram trending-audio finding and the Supademo API's non-existence — and absence from one doc page is weaker evidence than a stated prohibition.
