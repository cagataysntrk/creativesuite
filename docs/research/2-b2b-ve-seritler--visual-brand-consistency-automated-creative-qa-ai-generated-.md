## Özet

The consistency problem has largely moved from "train a LoRA" to "pass reference images at inference". As of Aug 2026 the three strongest brand-consistency levers are all first-class API parameters: Google's Gemini image models expose explicit slots (gemini-3-pro-image: up to 5 style-reference + 5 character-consistency images, 14 refs total; gemini-3.1-flash-image: 3 style + 4 character), BFL's FLUX.2 accepts up to 10 simultaneous reference images and markets "best character / product / style consistency available today", and Recraft lets you POST up to 5 brand images once to mint a persistent style_id for $0.04 that every later generation reuses. Recraft's style_id and Ideogram's style codes/character reference are the closest thing to a deterministic "brand handle". LoRA training is now the fallback, not the default — but it is cheap: fal's flux-lora-fast-training is a flat $2 per 1000-step run with `is_style: true`, needs ~4-20 images, and Ideogram sells a self-serve custom model at $40.

Licensing is the trap. FLUX.1 [dev] and FLUX.1 Kontext [dev] are under the FLUX.1-dev **Non-Commercial** License — unusable for Upcytech client work self-hosted without a paid BFL commercial licence. The commercially safe open lane is Qwen-Image / Qwen-Image-Edit-2511 / Qwen-Image-2.0 (Apache-2.0, multi-image reference, 4GB-VRAM offload path) plus FLUX.1-schnell and FLUX.2 [klein] (Apache-2.0). Likewise BiRefNet is MIT but Bria RMBG-2.0 is CC BY-NC.

Automated QA is fully solvable locally and free: culori gives CIEDE2000 Delta-E against brand tokens, node-vibrant/sharp extract palettes, transformers.js v4 runs CLIP in Node for brief-adherence and logo presence, and LAION aesthetic predictor / HPSv2 / t2v_metrics (VQAScore, PickScore, ImageReward) score quality. The premium lane is a Claude Haiku 4.5 ($1/$5 per MTok) or gpt-5-mini vision rubric judge at well under $0.01 per image.

**Gemini 3 Pro Image ("Nano Banana Pro")** — Turkey availability confirmed at ai.google.dev/gemini-api/docs/available-regions (listed as both 'Türkiye' and 'Turkey'). No free tier on ANY Gemini image model — do not plan a free lane around it.

**Gemini 3.1 Flash Image ("Nano Banana 2")** — Fewer reference slots than Pro (3 style vs 5). For a single-brand system 3 style refs is usually enough; reserve Pro for when you also need character/mascot locked.

**Gemini 3.1 Flash Lite Image** — Lite is capped at 1K resolution, so it cannot produce final 4K deck/print assets. Exploration only.

**FLUX.2 [pro] / [flex] (Black Forest Labs API)** — [flex]'s exposed steps/guidance is the only mainstream premium API that lets you pin generation params, which is what a deterministic dual-lane pipeline actually wants.

**FLUX.1 [dev] and FLUX.1 Kontext [dev]** — THIS IS THE SINGLE BIGGEST LICENCE TRAP IN THIS DOMAIN. You may still use FLUX.1/Kontext legally via a hosted API (BFL, fal, Replicate) because the provider holds the commercial licence — the restriction bites only on self-hosted weights.

**FLUX.1 [schnell] / FLUX.2 [klein]** — UNVERIFIED: the FLUX.2 blog summary asserted both [dev] and [klein] are Apache-2.0, but the BFL GitHub licence table only lists FLUX.1 variants and shows FLUX.1-dev as non-commercial. ### Öneriler

- ARCHITECTURE — make the brand a DATA OBJECT, not a prompt string. Create brand/tokens.json in the repo as the single source of truth: colors (OKLCH + hex + role), typography, spacing, logo safe-area rules, tone-of-voice fragments (Turkish), negative-prompt list, and an approved_examples[] array of image paths. Every pipeline step — free or premium — compiles this ONE object into its lane-specific payload. This is the design-token -> generation-parameter bridge you asked about (item 7), and it is what makes the dual-lane requirement tractable: one token file, two compilers.
- THE TOKEN COMPILER, concretely. colors -> (a) prompt fragment 'dominant palette: deep indigo #1a1a4e, warm amber #f5a623' AND (b) the QA threshold set for Delta-E checking. typography -> never ask the model to render brand type; generate type-free backgrounds and composite real text with sharp + your actual font files. This is the ONLY reliable path to font compliance and it also solves Turkish diacritics (ğ ı ş ç ö ü), which image models still mangle. spacing -> safe-area rectangles that sharp uses for logo placement and that the QA step verifies. tone -> Turkish copy fragments injected into the LLM copywriting step, never the image step.
- CONSISTENCY LADDER — climb it in this order, stopping as soon as quality is acceptable. Rung 1 (free, zero setup): 3-5 approved brand images passed as reference images to Qwen-Image-Edit-2511 locally via ComfyUI. Rung 2 ($0.04 once): mint a Recraft style_id from 5 brand images, then generate at $0.035/image — best consistency-per-dollar in the whole domain. Rung 3 ($0.045-$0.134/image): Gemini 3.1 Flash Image / 3 Pro Image using the explicit style_reference (3-5) and character_reference (4-5) slots. Rung 4 ($2): only if rungs 1-3 fail, train a style LoRA on fal with is_style:true, 1000 steps, 10-20 images. Do NOT start at rung 4 — that is the stale-training-data instinct.
- PRODUCT-SHOT PIPELINE (your real differentiator for sales decks and demo videos). Never let a model draw your UI — it will hallucinate the product. Instead: (1) capture the real screenshot with Playwright, which you already have available; (2) BiRefNet or rembg for the cutout if compositing a device/product; (3) generate ONLY the background/scene with the brand style applied; (4) composite with sharp, adding a synthesized soft drop-shadow (a blurred, offset, darkened alpha mask of the subject — pure sharp, no model needed); (5) if the lighting mismatch is visible, pass the composite through an instruction edit ('match the lighting of the subject to the scene, do not change the screen content') — Gemini or FLUX.2 premium, Qwen-Image-Edit free. This keeps the pixel-accurate product truth intact, which is non-negotiable for a B2B demo.
- QA GATE — build it as a scored pipeline stage with a hard threshold, running FREE by default. Five checks, all local: (1) COLOUR — node-vibrant extracts the palette, culori differenceCiede2000 compares each dominant colour to the nearest brand token in OKLCH; fail if min Delta-E > 5, warn at > 3. (2) LOGO — since YOU composite the logo with sharp, verify by re-reading the output region and comparing to the source logo pixel-wise, not by ML detection. Deterministic, free, 100% reliable. Only use OpenCV template matching or CLIP for logos the MODEL generated, which you should avoid entirely. (3) BRIEF ADHERENCE — CLIP via transformers.js, cosine similarity between image embedding and brief text. (4) AESTHETIC — LAION improved-aesthetic-predictor MLP on the CLIP embedding you already computed; marginal cost zero. (5) SAFETY — NudeNet in its Docker container. Premium lane ADDS a sixth: Claude Haiku 4.5 rubric judge at under $0.01/image, with the brand guide cached via cache_control so cache hits cost 0.1x.
- VQAScore BEATS CLIPScore for 'does this match the brief' and you can implement it in 20 lines without the framework. Ask a VLM 'Does this image show {brief}? Answer yes or no' and use the probability/logprob of 'Yes' as the score. This handles compositional briefs ('a laptop showing a dashboard, on a desk, warm morning light') that CLIPScore scores almost randomly. Run it against Claude Haiku 4.5 or gpt-5-mini rather than installing t2v_metrics, whose good models need 40GB+ VRAM.
- HUMAN-IN-THE-LOOP + PREFERENCE LEARNING WITHOUT TRAINING (item 5). Generate N variants (4 or 8), auto-rank them with HPSv2 — its API is literally designed to score a list of images from one prompt — then show the human only the top 4 in a grid with one-click accept/reject and an optional short reason. Persist every decision to Langfuse (self-hosted, free) as a dataset row: {prompt, params, seed, scores, verdict, reason}. Then the feedback loop needs NO training: on the next run, inject the last 5-10 ACCEPTED images as reference images (all the models above take multiple refs) and put the last few rejection REASONS into the prompt as explicit negative constraints. This is in-context preference learning and it compounds immediately, unlike a LoRA that needs a retraining cycle.
- SEED AND DETERMINISM. Persist seed + full parameter set + prompt version hash for every generation, and store them in the asset's manifest entry. ComfyUI gives you complete seed recovery from generated media, so free-lane assets are re-derivable from the file itself. For premium APIs, record the seed where the API exposes one and record the full request payload where it does not. Rule: an accepted asset must be reproducible or regenerable from data in the repo, or it is not really versioned.

Rationale: R2 has ZERO EGRESS FEES and costs $0.015/GB-month (50 GB = $0.75/month, with 10 GB free), whereas GitHub LFS gives only 10 GiB and meters BOTH storage and every byte downloaded — brutal for a pipeline that generates far more rejected variants than accepted ones. DVC adds a whole toolchain and a python dependency to solve a team-coordination problem you do not have. Concretely: commit assets/manifest.json with {id, sha256, r2_key, prompt, params, seed, qa_scores, verdict, campaign, created_at} per asset; keep bytes in R2; write a tiny sync script. Git stays fast and diffable, history is complete, and pruning rejected variants is just an R2 delete (free) plus a manifest edit.
